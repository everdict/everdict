# R16 — SkillNet: repositories, compositional benchmarks, and task-specific wikis

SkillNet combines a large skill repository, creation/evaluation tools, a relation graph, the SkillNet-Gym benchmark, and the SkillNet-Fabric routing method. These are distinct contributions with different evidence. The v3 report describes over 600,000 repository skills, a 159-task synthesized benchmark, and routing experiments using separate candidate pools. This note follows arXiv 2603.04448v3, including PDF tables omitted by the HTML rendering.[^1]

## Problem and research lineage

Reusable procedures are scattered across code repositories, documents, and execution logs. A larger collection alone does not solve the next task: an agent must identify applicable procedures, understand their prerequisites, and connect outputs to later inputs. SkillNet treats a skill as a package of procedural text and optional executable resources, and treats relationships between packages as a separate object worth modeling.

Related work includes ReAct for sequential tool interaction, ExpeL for extracting lessons from experience, skill repositories and retrieval systems such as SkillRouter/SkillRet, composition systems such as AgentSkillOS, and benchmarks such as SkillsBench. The repository supports creating and organizing artifacts; Gym probes construction and composition; Fabric proposes a routing implementation. None of these should be conflated with proof of unlimited autonomous skill improvement.[^2]

## Repository construction and ontology

The creation pipeline accepts trajectories/conversations, GitHub repositories, office documents, and direct prompts. LLMs extract reusable procedures and package them with metadata. Curation combines directory/Markdown hash deduplication, rule/model quality checks, categories/tags, multidimensional evaluation, and consolidation. Exact-content deduplication alone does not establish functional uniqueness.[^3]

The ontology has a taxonomy of broad categories and fine tags, a graph of skill entities, and a package layer for grouped releases. Four important relations have different semantics: `similar_to` suggests alternatives; `depend_on` expresses a prerequisite; `compose_with` expresses a plausible workflow handoff; and `belong_to` expresses a component relationship. Replacing one edge type with another can change the plan. Similar implementations are not necessarily consecutive steps.

For an illustrative data workflow, a parsing skill may produce a normalized table that a visualization skill can consume. A dependency on an authentication setup skill is different from that data handoff. A second parser may be an alternative rather than another mandatory action. A useful graph needs evidence about inputs, outputs, and conditions, not just semantic closeness between descriptions.

## Five-dimensional quality evaluation

Skills receive Good/Average/Poor ratings for safety, completeness, executability, maintainability, and cost awareness. Most assessment uses an LLM guided by rubrics; code/tool-containing skills also receive sandbox execution checks. The safety score is explicitly a repository curation signal, not deployment-level security clearance. The limitations acknowledge that many skills still lack rigorous systematic assessment.[^3]

For evaluator validation, 200 randomly sampled skills are independently reviewed by three PhD-level computer-science annotators. Reported mean absolute error is below 0.03 and quadratic weighted kappa exceeds 0.90 across dimensions. This establishes strong agreement with those human rubric judgments in that sample. It does not measure all future runtime failures, prove every dependency is correct, or establish that the full repository has been exhaustively executed.

The overall repository count and the smaller evaluated subsets must remain separate. An artifact can be well organized and plausible while failing on a task, and a successful individual execution does not establish generality across its declared scope.

## Experiment family 1: experience-derived skills in simulated environments

The first evaluation uses ALFWorld household tasks, WebShop shopping, and ScienceWorld laboratory tasks. These are partially observable sequential environments: the agent chooses actions from incomplete observations. Benchmark-specific skill collections are synthesized from ETO expert trajectories, which the authors state do not overlap the seen/unseen evaluation splits. Four executors are tested: DeepSeek V3.2, Gemini 2.5 Pro, o4 Mini, and Claude Sonnet 4.6.[^4]

Baselines include ReAct, ExpeL, and random expert-trajectory few-shot prompting. The SkillNet condition retrieves/activates relevant skills during execution. Table 1 reports mean reward and steps, with seen/unseen distinctions where provided. For Gemini 2.5 Pro on unseen ALFWorld, reward changes from ReAct 61.94 to 91.04 and steps from 19.18 to 11.96; WebShop reward changes from 31.66 to 53.02 and steps from 22.12 to 14.91. These illustrate gains under a particular executor and environment.

The headline reports roughly 40% higher average reward and 30% fewer steps relative to ReAct. Those are author aggregate comparisons, not 40 percentage points on every benchmark. The treatment includes expert-derived content and the way skills are accessed; the experiment does not isolate ontology edges, each quality rubric dimension, or a long-term evolution process. Step reductions also need outcome-aware interpretation: terminating unsuccessfully can be short, so reward and steps should be read together.

## SkillNet-Gym: synthesizing tasks from compositions

Gym constructs a smaller skill-centered graph from community skills, supporting documentation, and processable input files. Some supporting documents are synthesized when suitable originals are unavailable. The pipeline removes near duplicates, extracts pre/post scenarios, embeds them, and proposes links where one skill's resulting state can satisfy another's prerequisite. An LLM checks those handoffs. Scenario clustering and source evidence support the graph; a model-approved edge is still an inferred compatibility claim.[^5]

Task candidates sample chains, fan-out, fan-in, and diamond structures, usually involving two to five skills. Edge confidence, similarity, structure diversity, and hub penalties influence selection. An agent explores the proposed workflow on actual files and writes a report. That report guides generation of the instruction, reference solution, value-level test script, and minimal Docker environment.

The distinction between topology and skill count is useful. In a chain, errors propagate serially. Fan-out creates several outputs from a shared input. Fan-in requires compatible intermediate results before a combined step. A diamond combines branching and reconvergence, making state and format compatibility especially important. These are structural demands, not simply “more skills means harder.”

## Gym quality control, difficulty, and scoring

Quality control checks instructions, solutions, tests, and difficulty. A verifier agent reviews reference-solution trajectories; failures can trigger bounded retries. Generated tests must accept the reference and cover instruction requirements, with additional rubric review and preliminary rollouts. Tasks solved by GLM-5.1 in three no-skill trials are filtered out. Three annotators with at least master's-level computer-science training review retained tasks, with reported Fleiss kappa 0.834.[^5]

These steps reduce obvious errors but create selection and circularity concerns. Instructions, reference artifacts, and tests share a generation lineage; agreeing with the generated reference is weaker than independent verification. Filtering on one model intentionally changes the task distribution. The final 159 tasks are split post hoc into 77 Easy and 82 Hard cases using observed performance while balancing domains; difficulty is therefore an analysis label, not an independent predeclared treatment.

Construction evaluation compares no skills, supplied official skills, and skills compressed from upstream documents using a skill creator. Each task is independently attempted three times; success requires passing all tests, and Avg@3 averages success rather than choosing the best attempt. Composition evaluation separately asks for skill nodes and dependency edges from a pool of over 2,000 skills. Complete recovery is binary; it is not the same as executing the workflow successfully.

## Gym results, construction controls, and failures

Eight model configurations are tested with Claude Code or Codex. The prose names GPT-5.3 Codex, while PDF Table 3 labels that row GPT-5.4 mini; this internal identifier discrepancy prevents silently treating the row as a verified exact model configuration.[^6]

Representative Table 3 outcomes show why aggregate slogans are inadequate. Sonnet 4.6 rises from 62.34 to 74.03 on Easy tasks and 20.73 to 36.59 on Hard tasks with official skills. Haiku 4.5 falls from 59.09 to 55.84 on Easy while improving from 16.46 to 26.22 on Hard. GPT-5.4's Hard score is 28.66 without skills, 37.20 with official skills, and 26.83 with generated skills. One-shot compression can remove useful conditions, but generated skills also beat official ones in some cells.

The additional SkillSeeker construction baseline shows model-dependent tradeoffs rather than one consistent winner. In the wild-pool execution check, Kimi-K2.6 changes from official-skill 74.03/34.15 Easy/Hard to 66.23/25.61, and GLM-5.1 from 71.43/32.93 to 66.23/24.39. Supplying the right skills and making an agent find them are materially different conditions.

Direct agents recover a complete required skill set only 18.83% on average in the composition comparison. SkillRet reaches 59.12% complete retrieval with higher recall but low precision at the evaluated top-ten budget. Direct-agent orchestration completeness is 18.36%, compared with 29.49% for an adapted AgentSkillOS baseline. That adaptation uses a GLM-5.1 selector over SkillRet candidates rather than AgentSkillOS's original expensive tree construction, so the comparator must be described precisely.

Failure analysis attributes 59.6% of inspected negative cases to knowledge bias and 40.4% to instruction override. Examples include wrong APIs/parameters, incorrect input selection, workspace assumptions, budget exhaustion, output-schema drift, and skipped preprocessing. These percentages describe an audited failure subset, not all skills in the repository. Domain and topology analyses find both gains and regressions; they are associations across different tasks, not controlled proofs that one topology causes improvement.

## SkillNet-Fabric: a wiki between retrieval and final selection

Fabric separates candidate availability from final set formation. Build time extracts source-linked capability contracts, typed relations, retrieval indexes, and linked wiki pages. At task time, BM25 and dense retrieval are fused by reciprocal rank; seeds expand through relations to a maximum candidate count L. A task-specific wiki retains the candidates and evidence explaining their inclusion.[^7]

An Explorer starts from the index and contract cards, selectively reads full skill sources, and compares local relations. It chooses at most K skills with explanations of their contributions. A Planner combines the task, selected skills, and evidence into an execution prompt. The wiki is therefore a routing context, not a record proving the selected workflow will succeed.

The distinction between L and K is fundamental. Increasing L can make a missing prerequisite available, while increasing K lets the final set include more skills. A larger candidate space can also overwhelm comparison and add distractors. Neither a larger pool nor a longer prompt guarantees better final coverage.

## Fabric routing and downstream experiments

SkillRouter Hard has 75 scored tasks and 79,141 candidates. Fabric uses BGE M3 embeddings, depth-two expansion, 100 seeds, and L = 1,000, with K = 5 or 10. GPT-5.6 Terra is the reported Explorer. At K = 10, recall is 74.80% and complete coverage 60.00%, versus the official SkillRouter comparator's 69.42% and 50.67%. At K = 5, Fabric reaches 67.91% and 49.33%. This measures reference-set recovery, not task completion.[^8]

Downstream SkillsBench uses 87 tasks and mean verifier reward. Fabric reaches 46.08 with GPT-5.4 mini versus 29.63 without skills, 44.22 with reference skills, and 41.68 with SkillRouter. With GPT-5.6 Terra it reaches 66.67 versus 46.26 without skills, 60.66 with reference skills, and 57.07 with SkillsVote. Reported overall confidence intervals are broad and overlap; a higher point estimate alone is not a demonstrated significant pairwise advantage. The same model routes, plans, and executes within each condition.

AgentSkillOS evaluates 30 tasks over pools of 53, 500, and 1,000 skills. Scores are Bradley–Terry preference-derived values rescaled to 0–100, not percentages of objectively solved tasks. Fabric's pool means are 64.21 with GPT-5.4 mini and 83.00 with Terra, ahead of the reported comparators. These values depend on the comparison/judging setup and cannot be merged with SkillsBench accuracy into one leaderboard.

## Fabric component ablations and candidate-pool sweep

The wiki ablation uses all 30 AgentSkillOS tasks, GPT-5.4 mini, and the 500-skill pool. Removing different components changes both evidence access and navigation cost.[^9]

| Wiki condition | Bradley–Terry score | Mean Explorer tokens |
|---|---:|---:|
| Complete wiki | 65.51 | 27.82k |
| Without graph expansion | 54.15 | 16.66k |
| Without relation evidence | 53.05 | 30.26k |
| Without contract cards | 49.80 | 34.23k |
| Without complete sources | 48.12 | 24.42k |

Cards and relation evidence can reduce reading cost while helping final decisions; full sources and graph expansion can justify additional work. No component wins every task category. The complete condition has the strongest overall and minimum-category score in this comparison. Its 65.51 is the ablation evaluation's value, while the main 500-pool table reports 65.20; preserve the separate runs/tables rather than silently substituting one number.

A second study varies L from 10 through 10,000 and then exposes the entire 79,141-skill pool, with K fixed at ten and three Explorer models. Candidate complete coverage reaches 100% for the full pool by definition, but mean final complete coverage falls from 57.78% at L = 10,000 to 38.22% with the full pool. At L = 10, final coverage is 43.56%, close to candidate availability of 44.00%. Narrow pools are availability-limited; very broad pools can be selection-limited. The best tested size varies by Explorer, and the main routing table and sweep should remain separate experimental reports.

## Applications, limits, and the evolution claim

The paper illustrates scientific workflows, coding support, and integration with a community agent platform. These are application scenarios, not additional controlled performance trials. Future directions include feedback-driven evolution, model–skill co-adaptation, and sharing across agents. The limitations acknowledge incomplete coverage, uncertain skill quality, adversarial contributions, and the absence of a fully established requirements-to-agent pipeline.[^10]

Three scales recur: over 600,000 repository artifacts, a roughly 2,000-skill Gym composition pool, and the 79,141-candidate Fabric routing benchmark. They must not be interchanged. Similarly, rubric agreement, node/edge completeness, binary task success, fractional verifier reward, and preference scores are different measures. Much of the framework uses LLM-generated structure; provenance makes that structure inspectable but does not independently validate it.

## Implications and a proposed Everdict experiment

The most relevant change is to represent applicability, prerequisites, outputs, and relation evidence in the proposer's derived knowledge, then test whether it selects better combinations. Avoid treating an inferred dependency as platform authority. A driver may propose a relation or a composed candidate; the platform still evaluates the exact declared artifacts and preserves the evidence required for adoption.

Run a fixed-budget comparison of flat retrieval, retrieval plus source-linked contracts, and contracts plus typed relations with raw-source drill-down. Sweep candidate availability L separately from final composition size K. Measure complete requirement coverage, unnecessary skills, actual task success, cost, and unsupported relation claims on frozen confirmation tasks. Include alternative valid workflows so a reference graph does not become the only accepted solution by construction.

For evolving the graph, log whether an edge came from text interpretation, an observed handoff, or repeated held-out success. Test edges under changed input schemas and environments before generalizing them. Keep generated tasks in development/selection until their instructions, reference, and verifier have an independent review path. This applies SkillNet's organizing insight to Everdict's planned evolution loop while preserving the distinction between a useful proposed structure and confirmed improvement.
