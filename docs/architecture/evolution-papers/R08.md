# R08 — Gemini 3.5 Flash: reading a model card as an experimental contract

This resource describes the proprietary executor used in part of WikiSkill's experiments. It is a model card and evaluation-methodology document, not a paper introducing skill evolution. The relevant snapshot is the May 19, 2026 release; the scores below are release reports, not a current leaderboard. Understanding the card helps separate improvements to the executor from improvements to an evolved skill.[^1]

## Problem and relationship to earlier models

An agent needs a model that can interpret observations, choose tools, and follow a procedure over many steps. Higher reasoning effort may improve decisions but consumes time and tokens. Gemini 3.5 Flash offers configurable thinking levels and builds on the Gemini 3 Flash reasoning foundation. The card refers readers to predecessor cards for much of the architecture, training, and infrastructure description rather than publishing a complete new training recipe.

The predecessor report describes TPU-based training and JAX/Pathways infrastructure. This lineage does not disclose enough to reproduce 3.5 Flash's weights or independently attribute a score increase to one architectural change. For Everdict, the actionable object is an identified API executor with recorded settings. Treating its commercial name as a stable, fully specified algorithm would lose important experimental information.[^2]

## Capabilities and the meaning of context capacity

The model accepts text, images, audio, and video, with a one-million-token context window and text output up to 64,000 tokens. Input capacity is the amount the interface can accept; effective context use is the ability to locate and combine relevant information inside it. A large window does not imply that every buried observation will reliably influence the final answer.

An illustrative agent example is a trace containing thousands of tool messages and one early correction to a file path. The input can fit within the window while the model still follows the outdated path. Summarizing that correction into a skill can help retrieval, but an inaccurate summary can also destroy evidence. A skill-evolution experiment therefore needs both task outcomes and checks on which observations were retained. This example explains the distinction; it is not an experiment from the card.

## What the evaluation actually compares

The methodology generally reports pass@1, with exceptions identified separately, and uses the `gemini-3.5-flash` API with default sampling. Small evaluations can be averaged over repeated runs. Non-Gemini comparison scores are often supplied by their providers or external leaderboards, commonly at their maximum available thinking setting. Different agent harnesses and inference budgets therefore remain potential confounders.[^3]

Pass@1 is the success probability for one generated attempt. Averaging several independent pass@1 runs estimates that probability more reliably; selecting the best answer from several attempts is a different protocol. Similarly, an Elo rating measures relative judged performance against a comparison population, not the percentage of tasks completed correctly. These distinctions are necessary when carrying a benchmark number into an Everdict decision.

## Agent, coding, and tool-use results

The release table covers terminal operation, software engineering, tool selection and execution, desktop interaction, and professional work. Representative paired results are shown below. Each row has its own evaluation conditions; this is not a common-harness comparison across rows.[^1]

| Evaluation | Gemini 3 Flash | Gemini 3.5 Flash | Interpretation |
|---|---:|---:|---|
| Terminal-Bench 2.1, Terminus 2 | 58.0 | 76.2 | Terminal task success in the stated harness |
| SWE-bench Pro public | 49.6 | 55.1 | Software issue resolution, single attempt |
| MCP Atlas | 62.0 | 83.6 | Tool-use evaluation reported by Scale |
| Toolathlon | 49.4 | 56.5 | Long tool workflows in the authors' evaluation |
| OSWorld verified | 65.1 | 78.4 | Computer-use task success |
| GDPval-AA Elo | 1204 | 1656 | Relative professional-work rating, not accuracy |

For SWE-bench Pro, Gemini scores average five runs in an internal Antigravity harness. OSWorld averages five runs with 1080p screenshots, a 100-step limit, and PyAutoGUI-style computer-use tools. MCP Atlas, Toolathlon, and GDPval-AA draw on external evaluation providers. These are concrete conditions that matter when reproducing a claimed improvement. In particular, GDPval-AA Elo is not the original GDPval paper's professional preference percentage, and Terminal-Bench 2.1 is not interchangeable with an earlier benchmark version.[^3]

## Reasoning, vision, and long-context results

The card also reports Humanity's Last Exam, ARC-AGI-2, visual reasoning, scientific simulation, and long-context retrieval. Gemini 3.5 Flash scores 40.2 on the full text-and-multimodal HLE setting and 72.1 on the semi-private ARC-AGI-2 evaluation verified by ARC Prize. CharXiv reasoning is 84.2 and MMMU Pro is 83.6, both without tools in the stated methodology. These tasks probe different abilities; their values do not jointly establish reliable autonomous work.[^1]

MRCR v2 with eight needles reports 77.3 for the cumulative 128k setting and 26.6 for the pointwise one-million-token setting. The corresponding predecessor values are 67.2 and 22.1. The low long-context result illustrates why the advertised window should not substitute for measured retrieval quality. However, cumulative 128k and pointwise 1M aggregate different context conditions, so their difference is not a clean paired estimate of a single degradation rate.

BlueprintBench 2 is reported on a normalized scale, with the predecessor at zero. That zero is a normalization reference, not evidence that the predecessor solved no tasks. Readers should retain the metric definition whenever comparing scientific or agentic capability scores.[^3]

## Safety assessment and reporting limits

The card includes automated content-behavior evaluations, multilingual and image-conditioned checks, refusal behavior, human red teaming, and frontier-capability assessment. It states that launch criteria were met. It also explains that some assessment sets were improved, making them unsuitable for direct numerical comparison with older model cards. These are bounded developer assessments under their described procedures, not a guarantee about every tool-enabled deployment.[^1]

The public materials do not provide a full training-data mixture, weight-level reproducibility, or an ablation isolating every change from Gemini 3 Flash. Some comparisons use different providers' systems. API behavior may also change after the release snapshot. Consequently, the evidence supports a description of the released model's reported capability and evaluation setup; it does not identify which internal change caused each gain.

## Implications for Everdict evolution

The card is useful as a control specification. A skill candidate should carry the executor identifier, API version where available, thinking level, sampling settings, tool schema, context/output limits, and harness revision used to evaluate it. Store resolved settings rather than relying on mutable defaults. A later execution against the same product name may otherwise test a different system.

A practical experiment uses a fixed task split and the same executor settings to compare no skill, a fixed curated skill, and an evolved skill. Repeat each condition without choosing the best repeat. Report success, uncertainty, tool errors, latency, input/output/reasoning tokens, and total campaign cost. Separately rerun a small frozen control set when the provider changes the model, so API drift is visible.

For long-context workloads, compare the original trace, a bounded factual summary, and the evolved procedure while retaining the original evidence for audit. This separates memory compression from better instructions. The proposal fits Everdict's planned separation of train, select, and confirm: model-card scores can inform executor choice, while adoption still depends on the campaign's own frozen confirmation evidence.
