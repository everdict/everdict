# R28 — Qwen3.5: a reproducible executor is more than a model name

Qwen3.5 is a model-family release, not a paper introducing an external skill-evolution algorithm. The bibliography points to the February 2026 release; this explanation uses the official Qwen3.5-4B and 9B model cards and their configuration files, the small executors especially relevant to WikiSkill. These resources provide architecture, benchmark tables, and deployment conditions, while leaving the full training recipe and many evaluation details undisclosed. The inspected card contents are pinned to repository revisions rather than assumed immutable at a model-name URL.[^1]

## Why this resource belongs in an evolution review

An external memory or skill method changes the information and procedures supplied to an executor. Its outcome depends on whether that executor can read the skill, follow it, use tools, process images, and sustain a long interaction. A weak result can arise from poor memory content, insufficient executor ability, or a broken adapter. A strong result can arise from changing the model or inference settings at the same time as the skill.

Qwen3.5 offers open weights and local deployment, which make controlled executor experiments possible. Openness does not by itself make an experiment reproducible: weights, tokenizer, template, serving engine, precision, context settings, tool parser, and sampling all form the executable system. This resource contributes an experimental foundation, not evidence that Qwen's release process is the same as Everdict's candidate evolution.

## Hybrid architecture and what changes between 4B and 9B

Both models combine a vision encoder with a causal language model. Their language stacks have 32 layers arranged in eight groups: three Gated DeltaNet blocks followed by one gated full-attention block, each with a feed-forward network. The configuration explicitly alternates twenty-four linear-attention layers with eight full-attention layers.[^2]

Conceptually, the linear-attention part carries a recurrent summary of prior information, while full attention retains explicit token-to-token access. The hybrid aims to reduce the cost of using history while preserving richer retrieval at selected layers. This architectural description is not an ablation showing how much of a benchmark gain comes from each block.

| Property | Qwen3.5-4B | Qwen3.5-9B |
|---|---:|---:|
| Advertised language-model size | 4B | 9B |
| Hidden dimension | 2,560 | 4,096 |
| Language layers | 32 | 32 |
| Feed-forward intermediate width | 9,216 | 12,288 |
| Full-attention query / KV heads | 16 / 4 | 16 / 4 |
| Vocabulary, padded | 248,320 | 248,320 |
| Vision encoder depth | 24 | 27 |
| Vision encoder hidden width | 1,024 | 1,152 |

The 4B card explicitly ties output weights to token embeddings. The vision encoders also differ, so 4B-versus-9B is not a pure intervention that only widens the language model. Both cards advertise 262,144 native context tokens and extension to 1,010,000 using positional scaling. That counts the overall context budget; it is not guaranteed reliable recall of every item in a million-token input.

The family highlights mention sparse mixture-of-experts, but these particular 4B and 9B configurations use dense feed-forward networks. Do not describe every Qwen3.5 variant as an MoE model. Likewise, the family claims early-fusion multimodal training, broad reinforcement learning, support for 201 languages/dialects, and highly efficient infrastructure. The cards do not disclose enough data mixtures, rewards, compute accounting, or controlled component tests to reconstruct or independently attribute those claims.

## What the language experiments measure

The card compares the small models with GPT-OSS-120B/20B and Qwen3-Next/30B-A3B variants. It spans knowledge, instruction following, long-context use, mathematical reasoning, coding, general agents, and multilingual performance. Selected paired values show the pattern without pretending every benchmark measures the same capability.[^3]

| Benchmark | 4B | 9B |
|---|---:|---:|
| MMLU-Pro | 79.1 | 82.5 |
| GPQA Diamond | 76.2 | 81.7 |
| IFEval | 89.8 | 91.5 |
| IFBench | 59.2 | 64.5 |
| AA-LCR | 57.0 | 63.0 |
| LongBench v2 | 50.0 | 55.2 |
| LiveCodeBench v6 | 55.8 | 65.6 |
| BFCL-v4 | 50.3 | 66.1 |
| TAU2-Bench | 79.9 | 79.1 |
| DeepPlanning | 17.6 | 18.0 |

The 9B model is usually stronger here, but TAU2 is slightly lower. Neither the ordering nor statistical significance should be inferred from parameter count alone. GPT-OSS-120B scores 82.7 on LiveCodeBench v6 versus 65.6 for Qwen3.5-9B, so broad release language about improvements should not become a claim of universal superiority.

Benchmark footnotes change comparability. TAU2 applies airline-domain fixes discussed in the Claude Opus 4.5 system card to all compared models. MMLU-ProX averages 29 languages. WMT24++ is a difficulty-labeled, rebalanced harder subset evaluated with XCOMET-XXL across 55 languages. MAXIFE covers 23 English/multilingual prompt settings. These scores are not automatically interchangeable with every result bearing the original benchmark's name.

The tables generally lack uncertainty intervals, repeated-run counts, complete prompt manifests, contamination audits, and per-task results. They provide reported capability measurements, not a fully specified reproduction package for every row. The recommendation to allow long outputs is also not proof that each table used one common budget.

## Vision, documents, spatial tasks, and agents

The vision table includes visual STEM problems, general visual QA, OCR and documents, spatial understanding, video, computer interaction, tool use, and medical QA. For Everdict, this matters when a skill must inspect a rendered artifact rather than trust extracted text alone.[^3]

Qwen3.5-4B/9B obtain 86.2/87.7 on OmniDocBench 1.5, 70.8/73.0 on CharXiv reasoning questions, and 54.2/57.7 on MMLongBench-Doc. The table reports OSWorld-Verified 35.6/41.8 and AndroidWorld 58.6/57.8. Larger is again not uniformly better, and document understanding is distinct from editing an artifact successfully.

VideoMME differs with subtitles: 4B scores 83.5 with them versus 76.9 without; 9B scores 84.5 versus 78.4. Subtitles supply additional information, so the two conditions cannot be merged. BabyVision, TIR-Bench, and V* use slash-separated with/without code-interpreter conditions. These are different tool conditions, not error bars. MathVision uses a fixed final-answer-format prompt for Qwen, while other models receive the better score from runs with and without that format. The comparison therefore includes unequal prompt selection.

These are benchmark families, not a sequence of controlled architectural ablations. No result here isolates an external wiki, curator, or evolutionary search policy.

## Thinking mode, sampling, and history are experimental variables

Thinking is enabled by default. The card says the older textual `/think` and `/nothink` switches are not officially supported; disabling thinking uses the chat-template/API configuration. Self-hosted and Alibaba Cloud parameter placement differ. A request that merely contains the old switch may therefore fail to change the actual execution mode.[^4]

For general thinking tasks, the card recommends temperature 1.0, top-p 0.95, top-k 20, and presence penalty 1.5. For precise coding it recommends temperature 0.6 and presence penalty zero. These are task-dependent recommendations, not measured optimal values for Everdict. Non-thinking reasoning guidance is inconsistent within the card: the early tip gives top-p 0.95/top-k 20/presence 1.5, while Best Practices gives 1.0/40/2.0. An experiment must choose and record an explicit configuration instead of claiming to use one unambiguous default.

Recommended output limits are 32,768 tokens for most queries and 81,920 for hard competition problems. Historical conversation messages should omit earlier thinking content according to the Qwen3.5 guidance. Template implementations enforce this behavior, but custom adapters may not. Removing history content changes later inputs even when the stored transcript is identical.

## Serving efficiency, long context, and operational caveats

The cards demonstrate SGLang, vLLM, Transformers, and KTransformers integration, with separate reasoning and tool-call parsers. Multi-token prediction can support speculative decoding; the card lists different speculative configurations for the serving frameworks. A serving optimization must be measured on the actual workload rather than credited automatically as an algorithmic evolution gain.[^4]

The native context can be extended with YaRN. Static scaling may reduce short-context performance, and the card recommends enabling it only when needed. Video frame sampling and preprocessing limits also determine the information actually delivered to the model. An hour-long video URL does not imply that every frame was processed.

Some example prose says eight-GPU tensor parallelism while the 4B/9B commands specify a parallel size of one. These examples are not hardware feasibility guarantees for maximum-context production loads. The model cards list Apache-2.0 for the released artifacts; this is a resource description, not a deployment performed for this investigation.

## A concrete Everdict experiment

Use a factorial comparison: 4B versus 9B, each with no skill, a static skill set, and an evolved skill set. Freeze each model revision and run the same task families with declared context, output, tool, and sampling budgets. This separates the gain from a better executor from the gain from evolution and tests whether an evolved procedure transfers between executor capacities.

Add a small integration check before scoring: verify that tool calls reach the environment, thinking mode matches the declaration, images are actually processed, and the intended historical context survives serialization. Store the adapter and template digests with candidate evidence. A model name alone cannot establish that two attempts used the same system.

Measure end-to-end accepted-task cost, including failed runs, skill creation, retrieval, and serving overhead. Report memory and throughput under the intended concurrency rather than extrapolating from parameter counts. Keep dense/MoE comparisons and native/extended-context comparisons explicit. These are proposed controls for Everdict; the Qwen3.5 cards do not demonstrate that any particular curator or evolution policy succeeds.
