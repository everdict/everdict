# R39 — ReAct: reasoning, external actions, and the limits of episode-level adaptation

ReAct explains the execution loop underneath many later skill-evolution systems: a model alternates language-based planning with actions that obtain evidence or change an environment. It is foundational because a useful evolution system needs informative execution traces. The main prompting method, however, does not maintain a skill library or improve persistently across episodes. This note covers the pinned v3 paper, including all four benchmark families, hybrid inference, fine-tuning, error analysis, and human intervention.[^1]

## Problem, prerequisites, and relationship to prior work

A language model can produce a plausible multi-step answer using only its learned knowledge, but an early factual mistake can contaminate later reasoning. Conversely, an action-only agent can search or manipulate objects without maintaining a useful account of its goal, progress, or recovery plan. ReAct combines these capabilities in one context.

Chain-of-thought supplies intermediate language; self-consistency samples several reasoning paths and votes; WebGPT combines browsing with trained answering; SayCan connects language proposals to affordance estimates; Inner Monologue incorporates environmental feedback into planning. ReAct's contribution is a simple, broadly evaluated interleaving pattern, rather than the invention of language-model tools or all forms of feedback-based planning.[^2]

The distinction relevant to evolution is between **adaptation within an episode** and **learning across episodes**. Revising a plan after a failed search changes the current trajectory. Saving a reusable repair, testing it on later tasks, and promoting a versioned artifact requires additional machinery absent from ordinary ReAct prompting.

## Mechanism: language actions and real observations

The paper augments the environmental action space with language-only steps. An external action can retrieve a Wikipedia passage, inspect a page, or move an object. A language step updates the model's context without changing the external environment. Subsequent decisions condition on both kinds of steps and actual observations.[^1]

Language steps can decompose goals, track state, decide what evidence is missing, combine retrieved facts, or diagnose a failed action. For question answering, demonstrations generally alternate thought, action, and observation densely. For longer interactive tasks, the model can insert planning more sparsely when needed.

For example, a household instruction may require cleaning an object before placing it. Observing that the agent holds the object is evidence about possession, not cleanliness. A useful planning step identifies the missing cleaning operation and sends the agent to the sink. The cleaning result must still come from the environment. Saying that the object is clean does not make it so.

The generated language is inspectable output, not a guarantee of faithful access to the model's hidden causal process. Its factual claims remain hypotheses until supported by observations. This qualification matters when later systems distill a successful trajectory into a skill.

## Knowledge tasks: tools, demonstrations, and baselines

HotpotQA tests multi-hop answers using exact match. FEVER tests three-way claim labels: supported, refuted, or insufficient evidence. The paper reports FEVER label accuracy, not the full official evidence-plus-label FEVER score. The model receives the question or claim without oracle supporting paragraphs.[^3]

A deliberately small Wikipedia interface offers three operations. Search returns the first five sentences of a matching entity page, or nearby entity suggestions. Lookup returns the next sentence containing a requested string in the current page. Finish submits an answer. This creates a harder retrieval problem than supplying a strong retriever's best paragraphs directly.

The main model is PaLM-540B. Humans annotate six HotpotQA and three FEVER training examples. Baselines remove components from these demonstrations: Standard answers directly, CoT retains reasoning without tools, and Act retains actions and observations without reasoning. Main single-path methods use greedy decoding. CoT with self-consistency uses twenty-one sampled trajectories at temperature 0.7.

Two hybrids combine internal knowledge and external retrieval. ReAct-to-CoT-SC falls back to self-consistency if no answer appears within seven HotpotQA or five FEVER steps. CoT-SC-to-ReAct uses ReAct when the most common sampled answer has fewer than half the votes. That vote threshold is an agreement heuristic, not a calibrated probability of correctness.

## Knowledge-task results and what the comparisons establish

| PaLM-540B method | HotpotQA exact match | FEVER label accuracy |
|---|---:|---:|
| Standard | 28.7 | 57.1 |
| CoT | 29.4 | 56.3 |
| CoT self-consistency | 33.4 | 60.4 |
| Act | 25.7 | 58.9 |
| ReAct | 27.4 | 60.9 |
| CoT-SC → ReAct | 34.2 | 64.6 |
| ReAct → CoT-SC | 35.1 | 62.0 |

ReAct improves over Act on both tasks, but plain ReAct is below both CoT and Standard on HotpotQA. The best prompting results come from hybrids, not unconditional superiority of the interleaved format. A search interface can introduce retrieval and control errors even as it reduces unsupported factual reasoning.[^3]

The supervised comparison scores, 67.5 and 89.5, use different training and retrieval systems; they are contextual reference points. The paper also reports that hybrids using three to five self-consistency samples can match twenty-one-sample CoT-SC. That is a saving in sampled reasoning paths, not a complete accounting of all tokens, tool latency, and additional model calls.

Figure 2's FEVER curves do not align exactly with Table 1: its dashed CoT level is around 59 rather than the table's 56.3. Consequently, the table above uses Table 1 consistently; approximate curve values should not be silently substituted into the same comparison.

## Human error audit: grounded reasoning still fails

The authors inspect fifty correct and fifty incorrect outputs for each of CoT and ReAct: 200 examples stratified by outcome. Among correct answers, they judge 94% of ReAct reasoning valid, versus 86% for CoT. Correct final labels can therefore accompany invalid intermediate explanations.[^4]

Among sampled failures, the table attributes ReAct errors to reasoning at 47%, search at 23%, and label ambiguity at 29%, with no hallucination-class failures observed. CoT failures are classified as reasoning at 16%, hallucination at 56%, and label ambiguity at 28%. These are the paper's rounded category percentages, not population prevalence estimates or exact reconstructed counts.

The zero in one small category does not establish that ReAct never hallucinates. Failed disambiguation, missing retrieval results, repetitive actions, and incorrect conclusions from valid evidence remain possible. A correct answer can also arise through a mistaken comparison. The audit reports no broad inter-rater confidence analysis.

Some apparent errors reflect Wikipedia changing after the benchmark's labels were written. This demonstrates a conflict between current evidence and frozen answer keys, not automatic proof that the model's answer is correct. Reproduction requires source snapshots and an explicit policy for stale labels.

## Fine-tuning experiment: bootstrapping trajectories changes the model

A separate experiment generates 3,000 HotpotQA trajectories with correct final answers for each format, then fine-tunes PaLM-8B and PaLM-62B. Training includes the trajectory text; for action-based formats this includes observations. At inference, observations again come from tools. Thus these experiments change weights and must be separated from frozen-model prompting.[^5]

Batch size is sixty-four. ReAct and Act train for 4,000 steps; Standard and CoT use 2,000 steps for 8B and 1,000 for 62B. Different sequence lengths and training steps mean the comparison does not isolate format under equal training compute.

Figure 3 shows substantial gains for fine-tuned ReAct: approximately 25% exact match for 8B and 33% for 62B. The smaller fine-tuned ReAct model exceeds the displayed 62B prompting baselines. The 62B fine-tuned result exceeds the displayed 540B **single-path** prompting baselines, but not the best 35.1 hybrid or the 33.4 self-consistency table entry. The broader claim should retain that scope.

Correct-answer filtering is also weaker than verified-trace filtering. The error audit already shows that a correct answer can accompany faulty reasoning. Distillation therefore needs evidence about the operations and explanation being taught, not only the final string.

## ALFWorld: long-horizon action control and prompt sensitivity

ALFWorld provides text household environments with six task types. Evaluation uses 134 unseen environments. The authors annotate three training trajectories per type and select ordered pairs as two-shot prompts, producing six prompt variants. These are prompt permutations, not six independently trained model seeds.[^6]

ReAct achieves 57% average success, 71% best, and 48% worst across these variants. Act's best is 45%. ReAct with an Inner-Monologue-style annotation has 48% average and 53% best. Previously trained BUTLER reaches 22% with greedy decoding and 37% with beam search, reporting its best among eight trials.

The headline 34-point advantage is best ReAct 71 minus best beam-search BUTLER 37. The 26-point Act advantage also compares best prompts. The 57% average and 48% worst provide essential context for reproducibility; presenting 71% as a typical single run exaggerates robustness.

The IM-style control reannotates the same action trajectories with more frequent goal, subgoal, and environmental feedback. It removes richer completion judgments, state transitions, and common-sense reasoning. It therefore changes both content and density; it does not cleanly isolate the effect of thought frequency or reproduce every component of the original Inner Monologue system.

The supplied examples illustrate looping after an invalid action and prematurely treating an unclean object as ready for placement. One appendix Act prompt also retains a `think:` line despite its action-only description. This inconsistency in the printed prompt calls for checking the exact executable prompt artifact; it is not, by itself, proof of an implementation bug.

## WebShop: matching constraints instead of merely finding products

WebShop simulates shopping over roughly 1.18 million products and 12,000 instructions. The test contains 500 instructions. An agent searches, inspects details, selects options, and completes a simulated purchase. There is no real transaction. One human demonstration supplies the action trajectory; ReAct adds reasoning to it.[^6]

| Method | Mean reward score | Full success rate |
|---|---:|---:|
| Act | 62.3 | 30.1 |
| ReAct | 66.6 | 40.0 |
| Imitation learning | 59.9 | 29.1 |
| Imitation + reinforcement learning | 62.4 | 28.7 |
| Human | 82.1 | 59.6 |

Reward gives partial credit for matching requested attributes, while full success requires complete satisfaction of the benchmark's condition. ReAct improves full success by 9.9 percentage points over Act and 10.9 over the strongest trained baseline. Neither difference is a relative ten-percent gain.

The trained references use 1,012 human trajectories, with the RL system additionally using 10,587 instructions. These are different learning regimes, not equal-compute comparisons. Selected examples show why product titles alone are insufficient: the required variant may be available as an option on another product page. Reasoning can organize that check, but the final reward still depends on the actual chosen attributes.

## Additional backbone and human-intervention experiments

An appendix substitutes GPT-3 `text-davinci-002`. On a 500-question HotpotQA subset, the reported PaLM and GPT-3 results are 29.4 and 30.8; these are not the main table's full-setting ReAct score of 27.4. On ALFWorld, a prompt selected using PaLM yields 70.9 and 78.4 respectively. This supports feasibility on a second historical backbone, not universal transfer to current models.[^7]

A human intervention edits two generated planning statements in one failing ALFWorld episode and rescues the trajectory. This is an illustrative controllability case, without an aggregate intervention success rate. It changes neither the model weights nor a persistent skill. Its practical lesson is that a user can correct an explicit plan or state summary; it does not require treating generated private-style reasoning as a faithful mechanism or exposing hidden reasoning.

## Everdict evolution proposal and evaluation design

ReAct suggests a useful evidence boundary: store the task contract, action requests, actual tool observations, artifact states, and an optional concise planning summary as distinct fields. An agent's claim of completion must not replace the evaluator's artifact check. A proposed explanation for failure should retain links to the observations from which it was inferred.

An Everdict experiment could compare action-only execution, sparse state checks at meaningful transitions, and dense checks before every action. Hold the model, tools, task families, and total inference budget fixed. Measure verified completion, invalid-action loops, missing prerequisite checks, recovery cost, and generalization to held-out task families. Equal numbers of demonstrations alone would not equalize cost.

A second experiment can distill repeated, evidence-supported recoveries into an immutable candidate skill, then evaluate it through train, selection, and confirmation stages. Keep raw traces separate from the derived advice; record source versions and reject explanations unsupported by tool evidence. A useful skill might encode “verify formula results after recalculation,” while its applicability must still respect the user's workbook contract.

These are proposals for Everdict, not experiments performed by ReAct or already implemented platform behavior. ReAct supplies a feedback-rich executor; persistent evolution requires additional versioned memory, candidate search, and independent evaluation. The main risk is learning persuasive explanations of successful answers without learning the operations that made those answers valid.
