# R24 — SkillOS: learning a curator from the usefulness of future skills

SkillOS trains a small model to manage an external skill repository while keeping the task executor frozen. The curator learns insert, update, and delete operations from streams of related tasks, receiving reward partly from how well later tasks are solved. This directly addresses an Everdict question: how can a curator learn to preserve useful experience instead of merely producing plausible summaries? The paper supplies promising experiments, but its self-judged training signals, delayed credit assignment, and several reporting inconsistencies limit stronger claims. This note follows arXiv 2605.06614v1.[^1]

## Problem and relation to neighboring methods

A memory system needs both useful content and a policy for maintaining it. Always appending reflections can create redundancy; deleting aggressively can remove a rare but essential procedure; a powerful model can write advice that a smaller executor cannot use. The value of a curation decision often appears only on a later related task.

SkillOS relates raw-trajectory memory, distilled insights such as ReasoningBank, procedural memory such as MemP, and skill-augmented RL such as SkillRL. Its intervention is curator training: the executor's weights do not change, but the curator's do. At deployment, the trained curator continues changing external Markdown skills as the task stream unfolds. This differs from both a static distilled skill and Skill0's internalization into executor weights.[^2]

The “OS” analogy refers to file-like repository operations. The research representation is deliberately simpler than a general skill package: each skill is one Markdown file with name/description frontmatter and a body. Supporting scripts, resource folders, and a formal hierarchy are outside the implemented representation.

## The streaming execution and curation loop

At time t, the executor sees the current task and relevant skills, solves the task, and produces a trajectory. It does not see future tasks. BM25 retrieves up to five related skills. After execution, the curator receives the task, trajectory, self-judged outcome, and related existing skills, then emits structured insert/update/delete calls. Their application produces the repository for the next task.[^3]

The same repository can therefore be useful for one executor and harmful for another. A change to a skill description also changes retrieval, while a body change changes instructions after retrieval. Measured gains can involve both content and which skills become findable, even though the retriever itself is fixed.

A training instance begins with an empty repository and executes a whole group sequentially. Different sampled curator rollouts over the same task group create different repository histories, which change later executor trajectories. This is the source of delayed learning signal: earlier curation influences later outcomes. It is not an exact counterfactual evaluation of each individual edit.

## Constructing related task groups

For ALFWorld and WebShop, the method uses the benchmarks' existing task-type annotations. For reasoning, Gemini 2.5 Pro annotates a sampled DeepMath subset with five kinds of short phrases: topics, required skills, concepts/theorems, strategies, and pitfalls. Annotation avoids copying the final answer or task-specific identifiers.[^4]

A pair sampler builds groups that share a foundation but introduce something new. It matches phrases using exact overlap and greedy one-to-one embedding matches above cosine similarity 0.60, with all-MiniLM-L6-v2. It requires at least one shared concept and skill and at least one shared strategy/pitfall, limits topic similarity to 0.65, and keeps overall similarity between 0.30 and 0.85. A successor must add a concept or skill and satisfy a forward difficulty condition.

Candidates come from an inverted index over concepts, strategies, and pitfalls, capped at 2,000 entries; a random fallback pool of 200 catches semantic matches without exact phrase overlap. Relative field weights are 5/4/3/1/2 for concepts/skills/strategies/pitfalls/topics. The curriculum chooses upward and near-equal difficulty with probabilities 0.80 and 0.20, never downward in the main setting. Agentic groups contain ten tasks; reasoning groups contain five to twelve.

This makes reuse more likely and learning signals denser. It also engineers a more related stream than arbitrary production traffic. The filters express proxies for prerequisite structure; shared generated tags are not proof that one task causally teaches another. The grouping configuration is tuned by inspecting pairs from 200 held-out source tasks, and the cost of annotation is part of training preparation.

## Four reward terms and policy optimization

The task reward averages success on tasks two through the end of the group. The first task is excluded because it uses an empty repository before any curator intervention. The other terms reward valid function calls, judge-assessed content quality, and repository compression. Their weights are respectively 1.0, 0.1, and 0.05 alongside task reward weight one.[^3]

Function-call validity is the fraction of operations that execute successfully, averaged over the group. It checks whether a curator can use the interface, not whether an executed deletion was wise. Compression averages `1 − repository_tokens / curator_input_tokens` after each curation. This rewards concision relative to the current input, so changes in trajectory length can affect the score even without an absolute improvement in repository usefulness.

Qwen3-32B judges abstraction, reusability, actionability, and faithfulness. The printed judge prompt asks whether claims are supported by a trajectory, but its displayed input contains only the skill content. Without the supporting trace, faithfulness cannot actually be checked from that input alone. The main text describes a scalar score while the prompt returns a validity boolean, issues, and an explanation; the exact conversion should be pinned in a reproduction.[^5]

Eight independent curation-sequence rollouts are sampled per group. Their rewards are centered by the group mean, and the same resulting advantage is assigned to every curator output token in a rollout. A clipped policy-ratio objective updates the curator. This is coarse sequence-level credit: a beneficial early insertion and a harmful late update can receive the same sign of reward. Intermediate rewards improve signal density but do not solve exact edit attribution.

The main method says it discards the KL term to encourage exploration, while Appendix B lists a KL coefficient of 0.001. That is an unresolved configuration inconsistency; the actual training configuration is needed to reproduce the policy update.

## Self-judged training feedback versus final evaluation

The executor model also judges task outcomes used for curation/training. The reasoning prompt receives the problem and candidate solution, not a supplied reference answer, and asks the model to independently check the answer and derivation. The ALFWorld prompt asks for observed goal satisfaction and instructs the judge to ignore unsupported completion claims. These are useful judgment procedures, not ground-truth guarantees.[^5]

The WebShop prompt exposes a particularly important mismatch. It averages product-type match, attribute coverage, price compliance, and purchase completion, defining success at a score of at least 0.5, with a wrong product type forcing zero. Final benchmark success, however, requires the environment's reward to equal exactly 1, meaning all target requirements match. The learning success signal is therefore more permissive than the reported final SR.

Final evaluation uses environment outcomes for ALFWorld/WebShop, Math-Verify for AIME answers, and exact option matching for GPQA. Self-judged correctness can guide learning while an independent scorer measures final performance, but the two signals should not be reported as interchangeable. The paper does not provide a full calibration audit of its self-judge against these final verifiers.

## Training setup, test sets, and stream identity

The curator and training executor both start as Qwen3-8B. Training uses GRPO, learning rate 1e-6, batch size 32, eight rollouts per group, temperature 1, maximum curator prompt/response lengths 16,384/4,096, and sixteen H100 GPUs. The table gives 60/50/100 training steps for ALFWorld/WebShop/reasoning; reported duration is roughly three/five/two-and-a-half days.[^6]

ALFWorld uses 3,553 training tasks and 140 valid_seen tasks as its test population. This is the seen-environment validation split, not the usual unseen-environment generalization split. WebShop evaluates 500 held-out instructions after training from its training partition. Reasoning starts from roughly 33,000 annotated DeepMath problems and produces 20,000 grouped training instances, then evaluates AIME24 and AIME25, thirty questions each, and GPQA-Diamond, 198 questions.

Execution uses ReAct for interactive tasks, with at most thirty turns and history length three, and one CoT response for reasoning. Results average three independent runs with standard deviations. Additional executors are Qwen3-32B, Gemini 2.5 Pro, and, for an appendix experiment, Gemini 3.1 Flash Lite.

Because the intended evaluation is a stream with repository updates, test order, starting repository, and reset boundaries are part of the experimental identity. The paper explains training resets clearly but does not provide an equally complete test-stream ordering/state specification in these sections. Do not treat an evolving repository's later-task score as an ordinary independent per-question evaluation without recording that state.

## Main agentic results and a metric-label inconsistency

| Executor | ALFWorld no-memory SR | ALFWorld SkillOS SR | WebShop no-memory SR | WebShop SkillOS SR |
|---|---:|---:|---:|---:|
| Qwen3-8B | 47.9% | 61.2% | 9.8% | 16.5% |
| Qwen3-32B | 54.5% | 68.6% | 12.2% | 16.5% |
| Gemini 2.5 Pro | 66.4% | 80.2% | 38.4% | 41.3% |

For the 8B ALFWorld executor, the strongest external baseline is ReasoningBank at 55.7%, versus SkillOS 61.2%: a 5.5-point or approximately 9.9% relative improvement, reported as about 9.8% in the paper. Steps fall from 20.1 to 18.9, about 6%. The headline percentage is relative, not a 9.8-point gain.[^7]

The appendix calls ALFWorld Avg. SR a macro-average over six categories. But the displayed SkillOS 8B category scores average to 58.23%, while weighting them by the listed category counts gives 61.19%, matching the reported 61.2%. Thus the table behaves like an instance-weighted aggregate, not the stated macro-average. Preserve the reported value with this caveat rather than repeating the label uncritically.

Against the untrained SkillOS-base curator, ALFWorld improves 53.1→61.2 for the 8B executor and 70.7→80.2 for Gemini. The former is 8.1 points using the rounded table values, although the prose says 7.9. Against Gemini as curator, the trained 8B curator reaches 61.2 versus 50.7 with the small executor, but only 80.2 versus 79.3 with Gemini as executor. Training can improve executor alignment; the size of the advantage depends on the pair.

WebShop also reports partial-match scores: SkillOS 40.6/49.2/56.0 for the three executors, versus no-memory 33.3/41.5/48.6. Mean steps improve over no memory, but SkillOS is not fastest in every comparison: with Gemini, SkillOS-gemini uses 17.8 steps versus trained SkillOS 18.3. Environment steps exclude curator calls and offline training, so they do not establish the lowest complete deployment cost.

## Reasoning results and transfer experiments

For Qwen3-8B, SkillOS reaches AIME24 80.0%, AIME25 76.7%, and GPQA 64.6%, compared with no-memory 76.0/71.1/61.8. The three-dataset average rises 69.6→73.8. Qwen3-32B rises 74.0→79.7 on that average, and Gemini 2.5 Pro 81.8→88.6.[^7]

The average weights the two thirty-question competition sets and 198-question GPQA equally as datasets. It is not a pooled question-level accuracy. Three-run variation on AIME is substantial in some rows, and no paired significance analysis is supplied for every comparison. A stronger mean does not establish that every small difference is stable.

Cross-executor gains are obtained without training the curator on the new executor. Cross-domain plots transfer curators learned on one task family to another; most off-diagonal settings improve, with reasoning-trained curation transferring particularly well to interactive tasks. This transfers the curation policy, not simply a static math skill file into shopping. The paper's explanation that abstract decomposition/verification transfers better than environment-specific recipes is a plausible interpretation of those plots.

The additional Gemini 3.1 Flash Lite ALFWorld experiment reports 61.2% no memory, 66.0% ReasoningBank, 71.2% Gemini curator, and 73.1% trained SkillOS. Steps decline from 18.5 without memory to 15.5. SkillOS wins four of six categories; other methods still lead in Pick and Heat. The result supports the tested transfer, not universal executor compatibility.

## Ablations and what they isolate

The ALFWorld ablation uses 8B for both roles. Full SkillOS reaches 61.2% at 18.9 steps. Removing content-quality reward gives 58.6%/20.1; removing compression reward 60.0%/19.3; replacing related groups with random sequences 57.3%/20.6.[^8]

These comparisons support the tested intermediate rewards and task grouping. They do not isolate every reward component: the table does not remove the task reward or function-call reward, nor test all interactions. A compression ablation's gain is not evidence that arbitrarily shorter memories are better; it reflects the specific coefficient and task stream.

Grouping's larger effect is consistent with denser opportunities for reuse. It also suggests sensitivity to task arrival patterns. Production streams with unrelated tasks, abrupt changes, or rare recurring needs need explicit tests rather than assuming that the trained grouping advantage carries over unchanged.

## Repository behavior and qualitative examples

During training, insertion dominates first, updating becomes more common, and deletion remains relatively infrequent with a slight increase. Skills shift from generic tips to conditional branches, recovery procedures, and higher-level verification or strategy-adjustment advice. These are descriptive analyses of learned behavior, not separate controlled experiments showing that more headings or more updates cause higher success.[^8]

Usage analysis reports broader repository coverage, fewer skills used per example, and higher success among skill-using examples. This is consistent with better targeted content. It is not causal attribution by itself: tasks that use skills can differ from those that do not, and the report that every evaluation example uses a skill needs its precise denominator and initial repository state.

Examples include focused search near a lamp for a CD, a mathematical skill with alternative formula paths and explicit prerequisites, and a counting framework more concrete than a generic partitioning suggestion. A recovery example proposes finding a substitute after confirming an object is unavailable. That last idea requires a task-contract guard: if the user requires a specific object, substitution changes the objective rather than solving it. Learned generalizations must preserve applicability conditions.

## Everdict proposal: learn usefulness without granting authority

SkillOS motivates an Everdict curator objective based on later verified utility, not only how convincing or concise an entry sounds. A near-term experiment can compare append-only guidance, prompted insert/update/delete curation, and a trained curator over the same archived task streams. Keep executor and retrieval fixed, vary related versus shuffled streams, and replay each candidate from an identical repository snapshot.

Record every operation with its source traces, previous and new content hashes, and affected references. Deleting a derived skill must not delete the raw evidence ledger. Evaluate future success, regressions, retrieval coverage, repository size, and complete curation/execution cost. Include rare tasks to measure whether compression erases low-frequency but important procedures. If a learned curator checkpoint changes, give it a new candidate identity.

The documented first Everdict evolution loop separates driver-owned curation from platform-owned selection/confirmation and evidence integrity. A curator can propose changes or produce a versioned projection; it cannot promote its own candidate, alter the verifier, redefine success from full completion to a softer threshold, or rewrite historical results. The paper's WebShop reward mismatch makes this separation especially concrete.

A full SkillOS-style RL campaign is a later model-training extension, not a prerequisite for testing the curation idea. These are proposals rather than shipped Everdict changes. Read the method, metric definitions, actual judge prompts, and ablation table together; the paper's numbers are author-reported and have not been independently reproduced here.
