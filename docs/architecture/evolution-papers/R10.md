# R10 — AA-Omniscience: measuring knowledge and the decision to abstain

AA-Omniscience evaluates factual recall together with the willingness to admit uncertainty. It contains 6,000 short-answer questions across 42 topics in six domains. The central contribution is a scoring rule that penalizes incorrect guesses, plus a source-grounded question-generation pipeline and a 36-model evaluation. This note follows arXiv 2511.13029v1; its model rankings are the paper's historical snapshot.[^1]

## Why accuracy alone is incomplete

If a benchmark gives one point for a correct answer and zero for everything else, guessing has positive expected value whenever there is any chance of success. An agent optimized only for this score receives no incentive to say it lacks enough evidence. In an actual workflow, however, an incorrect fact can send later search, calculation, or editing down the wrong path.

The paper separates factual knowledge from knowledge reliability. A model may remember many facts while confidently inventing the rest; another may know fewer facts but decline more appropriately. Both matter even when tools exist: internal knowledge helps formulate useful searches, while recognizing uncertainty helps decide when external verification is needed. The benchmark itself deliberately removes tools and supplied context to isolate this starting point.

## Construction and relationship to factuality research

The six domains are Business, Humanities and Social Sciences, Health, Law, Software Engineering, and Science/Engineering/Mathematics. Topic selection emphasizes economic relevance, growing model use, and the need for precise facts. The authors gather authoritative, up-to-date publications and record an estimated first-answerable date where feasible. Fewer than 2% of questions first became answerable in 2025, so the collection is not mainly a test of that year's new information.[^2]

A GPT-5-based agent generates, filters, and revises questions from the source material. Questions should be difficult, unambiguous, self-contained, independent of incidental source details, and answerable with a short precise response. Version numbers and other disambiguating context are included when needed. Questions are tried on frontier models during construction to avoid saturation, making the final difficulty a selected property rather than an unbiased sample of ordinary user queries.

Related factuality evaluations include human-authored question sets, domain-specific knowledge tests, and methods that generate questions without grounding each generation in authoritative text. This work combines source grounding, automated revision, broad domain coverage, and explicit abstention scoring. It measures agreement with reference facts rather than merely whether an answer contradicts a supplied passage. Automated generation reduces authoring labor but does not remove the need to verify reference answers and their temporal scope.

## Answering and grading protocol

The answering prompt identifies the topic, requests only the answer, and tells the model to abstain when it does not know or needs tools/context. No tools or evidence documents are provided. A Gemini 2.5 Flash Preview September 2025 reasoning model classifies the answer as correct, partially correct, incorrect, or not attempted. The authors selected this judge for better agreement with their manual grading than the tested alternatives.[^2]

Correctness is semantic, so equivalent code expressions or inferable omitted context can be accepted. Numeric precision and identifiers receive different treatment. Partial answers are intended to be accurate but insufficiently precise or complete. The exact grader prompt is consequential: its examples include a numerically mismatched height accepted in an illustration about omitted units, and extra precision is treated differently across examples. These internal inconsistencies should be audited before copying the prompt into an evaluator; an LLM judge can learn the examples as well as the stated rule.[^3]

The full evaluation uses one pass, rather than averaging every model across repeated complete evaluations. A ten-repeat check on a sample of models reports small OI variation, with standard deviations below 0.005 in the paper's stated units. That stability check does not quantify grader bias or establish identical uncertainty for every model/domain. All comparison conditions must still retain model, prompt, and judge identities.

## The three metrics, with a worked example

Let c, p, i, and a count fully correct, partial, incorrect, and abstained responses, with N = c + p + i + a. The paper defines:[^4]

| Metric | Definition | Question answered |
|---|---|---|
| Omniscience Index, OI | 100 × (c − i) / N | Does correct knowledge outweigh incorrect guessing under equal rewards/penalties? |
| Accuracy | c / N | What fraction of all questions were fully correct? |
| Hallucination rate | i / (p + i + a) | Among responses not fully correct, how often was the result incorrect? |

The last denominator is easy to misread. It is **not** all attempted answers and is **not** all questions. For an illustrative 100-question run with 40 correct, 10 partial, 30 incorrect, and 20 abstentions, OI is 10, accuracy is 40%, and the reported hallucination rate is 50%. Incorrect answers among attempted answers would instead be 30/80 = 37.5%, a different statistic.

Partial and abstained responses both contribute zero to OI's numerator. A model that abstains everywhere receives OI 0. OI therefore needs accuracy and coverage alongside it; otherwise a system that never helps can outrank a system that knows much but guesses too often. The score encodes an explicit utility assumption, not a universal definition of reliability.

## What the scoring rule implies about confidence

Ignoring the partial category for a simple decision example, a model with probability q of being correct receives expected score q − (1 − q) = 2q − 1 by answering and zero by abstaining. It should answer only above q = 0.5 under this utility. If an incorrect answer has penalty λ rather than 1, the threshold becomes λ/(1 + λ). This derivation is explanatory analysis, not an additional result reported by the authors.

The important implication is that changing the penalty changes the desired behavior. A medical fact, a reversible code suggestion, and a low-cost search hypothesis may justify different downstream utilities. Everdict should declare its campaign's costs and acceptable coverage before optimizing a candidate, rather than silently changing the score after seeing which behavior wins.

## Main results and domain analyses

Only three of the 36 evaluated models have positive OI in the launch evaluation. Claude 4.1 Opus leads at 4.8 with approximately 36% accuracy. Grok 4 and GPT-5 high both reach approximately 39% accuracy, but their reported hallucination rates of 64% and 81% reduce OI. These rates use the non-fully-correct denominator above; they do not mean 64% or 81% of all answers were false.[^5]

The paper organizes models into relative knowledge/reliability quadrants. Claude 4.5 Haiku illustrates lower knowledge with more abstention: 16% accuracy and a 26% hallucination rate under this definition. The authors also compare OI with their broader Intelligence Index and find that broad benchmark capability does not reliably predict factual calibration.

Domain analysis finds different leaders: Claude 4.1 Opus on Law, Software Engineering, and Humanities/Social Sciences; GPT-5.1 on Business; Grok 4 on Health and Science/Engineering/Mathematics. Domain heatmaps are normalized within domains, so color is not an absolute accuracy scale. These are observational comparisons, not controlled experiments isolating a training method or proving that a model is suitable for every professional use in that domain.

## Size, cost, public subset, and limitations

The open-weight subset shows a positive association between parameter count and factual accuracy, but size alone does not predict OI. Some smaller systems obtain favorable reliability relative to larger peers. The cost analysis includes answering input, output, and reasoning-token charges and excludes grading cost. It is an evaluation-time historical price comparison, not total ownership cost or a current price quote.[^5]

Only 10% of the question set—600 questions—is public. It was sampled to match domain/category proportions and align aggregate model performance with the full set. The authors explicitly caution that public-subset domain/category estimates are too small to be reliable. WikiSkill's use of this public material should not be interpreted as evaluation against the undisclosed 6,000-question set.[^6]

Other limitations include English-only questions, substantial reliance on English-speaking-country sources, a single GPT-5 question-generation family, model-based grading, difficulty filtering, and the all-abstain loophole in OI. The authors discuss reducing the wrong-answer penalty as one possible future variant; that would define a different metric. No experiment here evolves a skill library or measures long-term knowledge maintenance.

## Implications and an Everdict experiment

The transferable idea is to evolve the decision boundary for using evidence, not merely increase answer volume. A skill can say when a source check is necessary, what evidence is sufficient, and when to return an unresolved result. Preserve those conditions when distilling successful traces; a confident final answer alone does not reveal whether the supporting process was sound.

Compare a baseline, an evolved answer-producing skill, and an evolved verification/abstention skill on frozen confirmation questions. Report c/p/i/a, coverage, accuracy, declared utility, retrieval cost, and errors caused by outdated sources. Separate a closed-book condition from a tool-enabled condition: adding search changes the task and should not be presented as a directly comparable AA-Omniscience score. Audit a stratified sample of judge decisions, especially numerical precision, qualified guesses, and partial answers.

At the proposal level, a factual claim in Everdict's curated knowledge can retain evidence, applicable version/time range, and unresolved contradictions. The driver may refine that projection, but the raw evidence remains available. This is an application inferred from the benchmark's reliability objective, not an implementation or adoption mechanism supplied by the paper.
