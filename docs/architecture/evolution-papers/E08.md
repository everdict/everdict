# E08 — Agentic Context Engineering: Evolving Contexts for Self-Improving Language Models

## Reading guide and evidence scope

Zhang et al., **2510.04618v3**, introduces **ACE**, a framework for accumulating and maintaining a detailed playbook while model weights remain fixed. This note covers the main text, all extended experiments and discussion appendices, and the actual prompts embedded as figures. It distinguishes offline optimization, online learning after each prediction, and later evaluations using other models. Experiments were not independently reproduced.[^1]

ACE is particularly relevant to Everdict because it separates generating experience, interpreting it, and editing a memory artifact. Its strongest finding is that incremental edits can preserve useful details that whole-document rewriting loses. Its strongest limitation is equally relevant: a coherent, well-preserved playbook can still accumulate wrong lessons when feedback is unreliable.

## The problem and the necessary background

**Context adaptation** changes instructions, demonstrations, memory, or supporting evidence presented to a frozen model. It differs from fine-tuning, which changes parameters. A detailed playbook can improve tool use by recording API return shapes, identity-resolution rules, pagination requirements, financial distinctions, or recurring failure patterns that a generic instruction does not supply.

The paper identifies two risks. **Brevity bias** means optimization favors short general instructions that omit important details. **Context collapse** means repeatedly asking an LLM to rewrite a growing memory can abruptly discard most of it. In an AppWorld case, a Dynamic Cheatsheet context shrinks from **18,282 to 122 tokens** between steps 60 and 61; accuracy falls from **66.7 to 57.1**, below the no-adaptation 63.7. This is an observed failure case, not proof that every summary or short prompt is harmful.[^2]

Relevant precursors include [Reflexion](E01.md), which stores verbal feedback; [TextGrad](R41.md) and [GEPA](R01.md), which optimize prompts with textual feedback; Dynamic Cheatsheet, which accumulates test-time experience; and workflow or linked-memory approaches such as AWM and A-MEM. ACE’s distinction is the explicit itemized representation and localized update mechanism. Its comparison with GEPA concerns the evaluated prompt-optimization setup, not a theorem that genetic search cannot optimize a detailed memory.

## How ACE works, step by step

A playbook consists of bullets with stable identifiers, text, and counters indicating judgments such as helpful or harmful. The text can contain a reusable rule, a failure mode, a concept, or code. On each task:

1. The **Generator** uses the current playbook to solve the task and produces an execution trajectory. The finance prompt also returns the identifiers of relevant bullets.
2. The **Reflector** reads the trajectory, available outcomes, relevant bullets, and, in supervised settings, the reference answer or code. It identifies errors, hypothesizes causes, proposes corrections, and labels bullet utility. Reflection may be refined for several rounds.
3. The **Curator** receives the existing playbook and reflection, then emits a small structured delta rather than rewriting everything.
4. Ordinary program logic merges the delta and assigns identifiers or updates metadata. Semantic-embedding similarity supports deduplication. Refinement can occur after each update or when the context reaches a size trigger.[^3]

The distinction between deterministic merging and correct learning is essential. A deterministic merger faithfully applies an incorrect lesson too. Helpful/harmful counts are model judgments, not counterfactual estimates of what would happen without a bullet. Similar embeddings also do not establish that two instructions are logically equivalent: a rule and its exception may look similar.

The published Curator prompts expose **ADD** as the available operation. They instruct the model to add only missing insights and leave existing material intact. The main text also discusses metadata updates, pruning, and deduplication, but the prompt alone does not specify a full contradiction-resolution or deletion protocol. Those mechanisms need explicit implementation; they cannot be inferred from the name “Curator.” The prompts favor concise individual additions and quality over quantity, so ACE’s argument is about retaining useful accumulated detail, not making every entry verbose.[^7]

The main experiments use **DeepSeek-V3.1 in non-thinking mode for all three roles**, batch size 1, up to five reflection rounds, and up to five offline epochs. Multiple epochs revisit training tasks. Online evaluation predicts a test item first, then updates memory from that item before the next item; all methods see the same shuffled stream. Main AppWorld online ACE includes an offline warmup, as clarified by the ablation. This is a different experiment from evaluating a frozen artifact on independent tasks.

## What the prompts and examples actually demonstrate

The AppWorld Generator inherits a Python REPL/API agent with demonstrations, API-documentation instructions, pagination guidance, and a completion protocol. ACE therefore adds learned context to an already structured agent. It does not discover every tool-use principle from an empty prompt. The Reflector’s examples diagnose identifying roommates through unreliable transaction descriptions and truncating playlist pagination. These are useful examples of turning a concrete trace into a scoped reusable rule.[^7]

However, printed prompts include reference-code and unit-test-report fields. A row marked “no GT labels” must remove or withhold the relevant oracle information at runtime; the appendix does not separately print every such prompt variant. Code execution success is available without an answer label, but it is not the same as successful completion of the user’s goal.

The example learned playbook contains identity-source rules, artist aggregation, and authentication troubleshooting. These illustrate domain detail, not independently audited universally correct procedures. A rule about where contact relationships live should be scoped to AppWorld’s API contract. Likewise, a memory instruction must not override a future user’s task conditions. The comparison GEPA prompt itself contains concrete domain procedures, showing that the empirical comparison is richer than “generic short prompt versus detailed instructions.”

## AppWorld: setup, metrics, and all main results

AppWorld evaluates multi-step API tasks on normal and challenge splits. **Task Goal Completion (TGC)** measures individual task completion; **Scenario Goal Completion (SGC)** requires success across the related tasks of a scenario. Averaging the four reported percentages is not the same as counting all solved tasks in one pooled dataset. All methods here build on the official ReAct agent. ICL supplies training demonstrations up to the context limit; GEPA uses DSPy’s heavy optimization setting; Dynamic Cheatsheet uses cumulative mode.[^4]

| Method | Adaptation feedback | Normal TGC / SGC | Challenge TGC / SGC | Four-metric average |
| --- | --- | --- | --- | --- |
| Base ReAct | None | 63.7 / 42.9 | 41.5 / 21.6 | 42.4 |
| Offline ICL | Training labels | 64.3 / 46.4 | 46.0 / 27.3 | 46.0 |
| Offline GEPA | Training labels | 64.9 / 44.6 | 46.0 / 30.2 | 46.4 |
| Offline ACE | Training labels | 76.2 / 64.3 | 57.3 / 39.6 | 59.4 |
| Offline ACE | No GT labels | 75.0 / 64.3 | 54.4 / 35.2 | 57.2 |
| Online DC | No GT labels | 65.5 / 58.9 | 52.3 / 30.8 | 51.9 |
| Online ACE, with warmup | No GT labels | 69.6 / 53.6 | 66.0 / 48.9 | 59.5 |

The offline supervised gain over ReAct is **17.0 percentage points**. Without GT labels, offline ACE still gains 14.8 points. Online ACE beats DC by 7.6 points on the average, but **loses normal SGC, 53.6 versus 58.9**. “Consistently better” therefore describes aggregate results, not every cell.

The paper’s headline average gain of 10.6% is an aggregation of selected comparisons, not the relative improvement over ReAct. Some prose numbers do not match the printed table: offline 59.4 minus ICL 46.0 is 13.4 points, and minus GEPA 46.4 is 13.0, rather than the prose’s 12.3 and 11.9. Use the explicit table conditions.

A September 2025 leaderboard snapshot shows IBM CUGA at about 60.3 across four metrics. ACE’s 59.4 is in a similar range, not higher overall; online ACE exceeds CUGA on challenge TGC and SGC. Different agent engineering and models prevent a controlled methodological comparison. This is a historical reference, not a current leaderboard claim.

## Finance, medicine, and SQL experiments

FiNER tests fine-grained financial/XBRL entity labels across 139 types; Formula tests financial calculations. The paper reports exact-answer accuracy for its evaluated tasks, not a clinical or financial deployment outcome. Offline methods learn from training data; supervised online methods receive a sample’s label **after** making its prediction. Label availability is part of the experimental treatment.[^5]

| Method and feedback | FiNER | Formula | Average |
| --- | --- | --- | --- |
| Base | 70.7 | 67.5 | 69.1 |
| Offline ICL, labels | 72.3 | 67.0 | 69.6 |
| Offline MIPROv2, labels | 72.4 | 69.5 | 70.9 |
| Offline GEPA, labels | 73.5 | 71.5 | 72.5 |
| Offline ACE, labels | 78.3 | 85.5 | 81.9 |
| Offline ACE, no labels | 71.1 | 83.0 | 77.1 |
| Online DC, labels | 74.2 | 69.5 | 71.8 |
| Online DC, no labels | 68.3 | 62.5 | 65.4 |
| Online ACE, labels | 76.7 | 76.5 | 76.6 |
| Online ACE, no labels | 67.3 | 78.5 | 72.9 |

Supervised offline ACE improves the average by 12.8 points over base and 9.4 over GEPA. But unsupervised online FiNER **regresses by 3.4 points**, and is also below unsupervised DC’s 68.3. On Formula, label-free online ACE exceeds supervised online ACE in this table. These results show feedback/task interactions, not a monotonic law that every extra label or every memory update helps. Figure 1 mixes offline FiNER and online Formula/AppWorld numbers; it should not be read as one uniform protocol.

The extended offline study uses 1,000 training examples for both ACE and GEPA, with separate GEPA validation sets of 372 for DDXPlus and 500 for BIRD-SQL. DDXPlus rises from **75.2 to 90.2**, compared with GEPA 76.4. This is a medical benchmark result, not demonstrated patient benefit. BIRD-SQL rises from **47.8 to 52.9** overall, versus GEPA 52.2. ACE wins the simple subset but loses to GEPA on moderate and challenging subsets. Crucially, this study uses a **GPT-4o-mini judge**, so its reported SQL score should not be relabeled as database execution accuracy. The overall score is not the unweighted average of the three difficulty percentages.

## Other models: algorithm portability, not fixed-playbook transfer

The appendix repeats adaptation after switching **all three roles** to each new model, with unchanged algorithm and prompts. This tests whether the method works across model families. It does not test transferring one frozen DeepSeek-generated playbook to an unseen executor.[^6]

On AppWorld, GPT-OSS-120B averages **34.6 base → 40.5 supervised offline ACE → 42.2 online ACE**; DC is 33.1. GPT-5.1 is tested on **normal only**, where its two-metric average is **54.2 → 60.2 → 65.8**. Its 65.8 cannot be compared directly with the four-metric DeepSeek 59.5.

On finance, supervised offline averages are **69.1 → 81.2** for GPT-OSS and **73.3 → 82.8** for GPT-5.1. Their label-free online ACE averages are 77.8 and 77.1. Llama-3.3-70B is tested on FiNER only: **62.5 → 64.9** supervised offline, 64.2 label-free offline, and 63.6 label-free online. Thus the appendix’s statement that online is always strongest is not supported by every table; supervised offline finance often wins. Main comparisons lack broad multi-seed confidence intervals, so small gaps should not be treated as established significance.

## Ablations and stress tests

The paper includes several distinct experimental families, which answer different questions.[^6]

- **Reflector and repeated epochs:** AppWorld average is 55.1 without both, 56.8 with reflection but one epoch, and 59.4 with the full offline setup. Reflection contributes 1.7 points in the first comparison, and repeated training contributes another 2.6; this does not isolate every reflection subcomponent or equalize total calls.
- **Offline warmup:** online average rises from 56.1 to 59.5. Main online ACE therefore benefits from prior offline work in addition to the test stream.
- **Incremental updates:** normal-only average is 56.9 with whole-context updating versus 70.3 with deltas, against base 53.3. TGC is 67.3 versus 76.2, and SGC 46.4 versus 64.3. The appendix’s 11.7%/27.8% drops are relative to the full scores; the absolute drops are 8.9/17.9 points.
- **Reflector strength:** with DeepSeek Generator/Curator fixed, FiNER is 76.6 using GPT-OSS reflection, 78.3 using DeepSeek, and 78.5 using GPT-5.1, against 70.7 base. A weaker reflector still helps here; this does not eliminate the need for usable feedback.
- **Deliberately harmful reflection:** inserting a harmful reflection every 100/50/25/10/5 iterations gives 78.2/78.2/77.8/77.0/76.1; every iteration gives **66.7**, below base. This is one controlled corruption pattern on FiNER, not a general robustness guarantee against poisoned evidence or targeted attacks.
- **Reflection rounds:** normal-only averages for 1/3/5/10 rounds are 61.3/65.8/67.6/65.2. More reflection is not always better, and this separate study’s five-round result is not identical to the main result.
- **Deduplication threshold:** FiNER is 77.0/73.9/78.6 at 50%/70%/90%. All beat base, but the 4.7-point spread is material and nonmonotonic.
- **Pruning trigger:** 10K/50K/100K tokens yield 78.6/78.4/78.3 on FiNER. A tenfold larger allowance does not improve this experiment. It measures trigger settings, not necessarily that every resulting playbook has exactly that length.

## Cost, latency, and unresolved accounting differences

The main cost table reports offline AppWorld adaptation at **9,517 seconds and 357 rollouts**, compared with GEPA’s 53,898 seconds and 1,434 rollouts: 82.3% less latency and 75.1% fewer rollouts. Online FiNER reports **5,503 seconds and $2.9**, versus DC’s 65,104 seconds and $17.7. Dollar figures are historical measurements, not present API price estimates.[^6]

The later fine-grained appendix uses **one epoch and one reflection round**, whereas the main setup allows five of each. It reports adaptation input tokens **204.1M → 39.3M** and output tokens **1.87M → 0.31M** versus GEPA. However, its “rollout” count goes **1,455 → 2,075**, an increase of 42.6%, with 90 ACE training queries versus GEPA’s 90 plus 57 validation queries. This cannot be merged with the main table’s “75.1% fewer rollouts” without reconciling configurations and counting units. The paper does not provide that complete reconciliation.

The detailed evaluation covers 160 queries: ACE uses **58.6M input tokens versus GEPA 27.0M**, and **270,652 output tokens versus 251,442**. The prose’s 115.0 versus 101.8 output tokens refers to **per rollout**, despite describing the surrounding discussion in per-query terms. Richer context is not free at evaluation time.

A separate GPT-5.1 caching study reports **91.8% input cache reuse**, reducing billed input-token cost by **82.6% compared with billing all ACE inputs as uncached**. This is not an 82.6% saving relative to GEPA, and does not include all output/adaptation charges. Cache discounts also do not prove that GPU memory or latency is independent of context length. Serving configuration, stable prefixes, cache lifetime, and changing playbook bytes matter.

## Concrete Everdict evolution experiments

ACE supports a focused curator experiment within the [proposed first evolution loop](../evolution-first-loop.md). The platform should retain the append-only evidence ledger; a driver can maintain a derived, versioned playbook. Curating that view must not rewrite the source history or change which observations are disclosed.

Compare three equal-budget arms: the existing bounded advice/history mechanism, a whole-document summary, and itemized delta curation. Match source observations, task-family exposure, executor budgets, and allowed context sizes. Add a raw-history retrieval baseline if it is necessary to distinguish preserved detail from a better retrieval policy. Freeze the selected artifact for independent confirmation; separately report online predict-then-update performance if testing continual adaptation.

Each proposed entry should contain a scoped claim, applicability conditions, supporting and contradicting evidence references, and a status such as tentative, supported, superseded, or rejected. Helpful/harmful counts may guide retrieval but must not authorize promotion. Test revision and removal explicitly: an ADD-only stream plus semantic deduplication does not demonstrate correction of a plausible but false rule.

Measure task success and regressions, retained rare-case knowledge, wrong-rule persistence, duplicate/conflicting entries, selection calls, total tokens, cache hits, and end-to-end latency. Include an experiment where feedback is missing or misleading. A curator that produces longer, more stable text while preserving a harmful lesson has improved storage behavior, not agent capability.

These are research proposals. The paper motivates separating generation, reflection, and curation; it does not show that Everdict needs new platform authority for the curator or that a learned playbook should become a new campaign subject before the current agent-capability contract is established.
