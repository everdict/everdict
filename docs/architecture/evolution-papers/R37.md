# R37 — Agent Skills survey: architecture, acquisition, deployment, and lifecycle governance

Xu and Yan's survey, version 4, organizes agent skills across architecture, acquisition, deployment, security, and open research questions. It proposes a trust-and-lifecycle framework, but does not run a new skill optimizer, comparative agent benchmark, or validated governance system. The experimental numbers it discusses come from other publications. Its value for Everdict is a map of what can evolve and what must remain under platform control.[^1]

## Scope, methodology, and how to read the evidence

The authors search arXiv, ACL Anthology, major machine-learning conference proceedings, and official technical publications using terms concerning agent skills, skill libraries, tool use, computer-use agents, and MCP. They focus on the skill abstraction rather than surveying every agent architecture. Computer-use agents receive substantial attention because they expose perception, element selection, and action failures clearly.

The methodology does not provide a fully reproducible screening flow, exact search dates and query strings, complete inclusion/exclusion decisions, or a risk-of-bias assessment. This is a structured narrative survey, not a quantitative meta-analysis. Its claims of priority and ecosystem convergence are interpretive, and historical repository popularity is not a capability evaluation.

The note below explains all major conceptual sections and empirical evidence families. It does not recursively turn every paper cited by this survey into an additional standalone item in the sixty-source collection. Where a cited claim affects Everdict's design, a few primary-source checks clarify its meaning.

## Architecture: a skill is a package, not only a sentence

A skill packages metadata, procedural instructions, and optional scripts, references, and assets. Progressive disclosure exposes a short name/description first, the main instruction body when activated, and detailed resources when needed. This allows a large resource package without putting all its contents into every prompt.[^2]

The important tradeoff is routing versus context. Metadata for every visible skill still consumes tokens; the survey's phrase “without context penalty” is too strong. A large collection can overwhelm selection even if each description is short. Conditional resources save context only when they are not loaded, and can fail if the agent never follows the pointer.

The survey contrasts skills with prompts, RAG, and tools, but the boundaries are not absolute. Prompts can be versioned and modular; RAG can retrieve procedures or code; tools can implement complex workflows. Skills provide a useful packaging and lifecycle convention rather than making those older techniques incapable of the same content.

The paper describes an execution lifecycle in which hidden context is injected and pre-approved tools become available. That is a host-specific behavior, not a universal permission grant inherent in Markdown. The inspected Agent Skills specification makes `allowed-tools` optional and experimental. The host must decide and enforce what is allowed; reading a skill cannot by itself authorize new operations.[^3]

## Skills, MCP, and three different tool-use improvements

MCP supplies a protocol for connecting to tools, resources, and prompts; a skill can explain how to combine those capabilities for a task. These are complementary layers. A protocol connection does not supply a complete procedure, and a procedure does not create an authenticated connection or permission boundary. Likewise, protocol sessions do not imply that external application data or server state disappears when a session ends.[^2]

The survey discusses tool discovery, programmatic orchestration, and usage examples. These address different failures: finding the right API, processing many intermediate results, and forming valid domain-specific arguments.

A primary-source check corrects one numerical attribution. Anthropic's November 2025 article assigns Opus 4.5's 79.5%→88.1% improvement to **Tool Search**, whereas the survey attributes it to Programmatic Tool Calling. The article separately reports a 37% token reduction for programmatic calling on complex research tasks, and 72%→90% accuracy for Tool Use Examples on complex parameter handling. These are different internal evaluations; their gains cannot be added or called an isolated benefit of Agent Skills.[^4]

## Six acquisition routes and what changes in each

Although the section introduces “four” modalities, its table and subsections contain six. They can be understood through the artifact and feedback each changes.[^5]

| Route | Mechanism | Evolution question for Everdict |
|---|---|---|
| Human authoring | An expert writes and revises a portable procedure | Which observed failure justifies a change, and how is it reviewed? |
| RL with libraries | Train a policy to create/use skills across task sequences | Is the gain in weights, external content, or their interaction? |
| Autonomous exploration | Generate curricula, explore software, accumulate lessons | Does task generation produce useful coverage beyond easy self-created tasks? |
| Structured skill bases | Encode parameters, preconditions, and composition graphs | Can applicability and dependency checks prevent invalid reuse? |
| Compositional synthesis | Select and combine reasoning components | Does the combination add capability without conflicts or excess cost? |
| Skill compilation | Replace parts of multi-agent work with reusable single-agent procedures | Which coordination behaviors survive compression? |

For human authoring, the survey uses provider and partner skill ecosystems as evidence of practical adoption. A star count or a curated directory is evidence of interest and distribution, not a measured success rate or proof of semantic correctness.

For RL, it describes SAGE's sequential rollouts: skills created on earlier tasks become available to later similar tasks, and a skill-related reward supplements outcome rewards. It reports AppWorld task completion of 72.0%, scenario completion of 60.7%, an 8.9-point scenario improvement, and fewer steps/tokens. The primary SAGE abstract confirms that the system uses a library accumulated across tasks and starts from a model supervised with expert experience. Consequently, the survey's later description of SAGE skills as exclusively internal and uninspectable is misleading; model training and external artifacts must be distinguished.[^6]

SEAgent combines a world-state model, curriculum generation, and a software guidebook, with specialist experience integrated into a generalist. The survey reports 11.3%→34.5% success on five novel software environments. CUA-Skill instead encodes parameterized execution and composition graphs and reports 57.5% on WindowsAgentArena. Agentic Proposing uses modular reasoning composition and reports 91.6% on AIME 2025 with a 30B solver. These are source-specific examples, not matched comparisons across the six routes.

The compilation work suggests that a single agent with an appropriate library can replace some multi-agent coordination, while skill selection degrades past a certain library scale. The survey does not supply enough controlled scaling details to turn that observation into a universal critical number of skills. Library similarity, description quality, routing, model capacity, and task distribution all matter.

## Deployment: separate perception, grounding, and execution

In a computer-use agent, perception reads the current screen, grounding maps an intended target to an actual element, and action changes the environment. A skill can improve the procedure while leaving grounding errors untouched. Conversely, a better grounding model can increase final success without any skill evolution.[^7]

The survey uses UI-TARS/UI-TARS-2 for unified action modeling and multi-turn RL, Agent S2 for generalist-specialist composition, and OpenCUA for an open data/training stack. It discusses UGround's large GUI-element dataset, synthetic grounding data, self-evolutionary grounding RL, and GUI-Actor's coordinate-free action head. These illustrate several changing layers of the system rather than one common skill intervention.

Reported examples include UI-TARS-2 at 47.5% on OSWorld and 73.3% on AndroidWorld, OpenCUA-72B at 45.0% on OSWorld-Verified, and a 7B grounding model at 47.3% on ScreenSpot-Pro. Different benchmark variants, observation interfaces, horizons, and model/harness combinations prevent treating these figures as a single leaderboard.

The benchmark discussion extends to long-horizon OS-Marathon, hybrid GUI/code work, SWE-bench, and function-calling evaluations. ScreenSpot-style element localization does not measure completion of an entire desktop workflow. A reported OSWorld-V score near a published human baseline also does not establish general operational superiority over people. These are historical survey examples, not current September 2026 rankings.

## Security evidence: three studies and three different meanings

The survey's first security study demonstrates that malicious instructions in a skill or linked resources can redirect an agent, including abuse of overly broad carried-over approvals. The mechanism is a trust-boundary error: externally supplied content is treated as authority. This is an existence demonstration of an attack path, not a prevalence estimate across every runtime.[^8]

The second study collects 42,447 skills and analyzes 31,132. It reports 26.1% with a detected vulnerability and 5.2% with high-severity patterns suggestive of malicious intent. The survey later associates 26.1% with the collected total, but the analyzed population is the relevant denominator. The primary abstract reports detector precision 86.7% and recall 82.5%, so these detections are not an error-free census. Its executable-script association is an **odds ratio** of 2.12, not automatically a 2.12-fold probability or causal effect.[^9]

The third study's original version reports 157 behaviorally confirmed malicious skills within a 98,380-skill collection, with 632 vulnerabilities and 54.1% of confirmed cases attributed to one actor. Multiple vulnerabilities can belong to one skill. Confirmed cases, detector-flagged weaknesses, and inferred intent are different categories; their percentages cannot be combined into one estimate of “malicious skills.” Detection coverage and sampling also limit prevalence claims.[^10]

For Everdict evolution, this evidence supports distinguishing observed behavior from declarations and keeping advisory content below platform authority. It does not require treating every procedural mistake as malicious or importing a new approval flow into ordinary authorized work.

## The proposed lifecycle governance framework

The survey contributes a four-gate design: static pattern/dependency checks, LLM semantic comparison of declared purpose and instructions, behavioral sandboxing, and comparison of observed behavior against a declared capability manifest. Each detects a different class of mismatch. Static checks miss novel semantics; semantic judges can err; sandbox executions cover only tested paths; a manifest requires runtime enforcement.[^11]

Four trust tiers then connect provenance and verification to progressively broader access. The prose places unvetted skills at the lowest tier and vendor-certified ones at the highest. Later text maps metadata to T1, full instructions to T2 and above, and executable resources to T3/T4. There is a small internal ambiguity: the earlier T1 description says instruction-only access, whereas the later mapping says metadata only. An implementation needs one explicit policy.

Runtime anomalies can cause demotion or revocation, while clean histories can support promotion. This is a proposed lifecycle feedback loop, not an evaluated security system. The paper does not report a gate benchmark, false-negative rate for the combined pipeline, enforcement implementation, or measured reduction in attacks.

Two design assumptions deserve modification. Vendor certification is provenance evidence, not justification for unrestricted capabilities. A clean history is evidence only about observed executions of specific bytes and environments, not all future behavior. A revised skill should not inherit every trust conclusion from an earlier version without checking what changed. Metadata itself is also text seen by the model and can carry misleading instructions.

## Seven research questions translated into measurable changes

The survey's complete agenda can become a concrete evaluation matrix.[^12]

| Open problem | Measurement that makes the claim testable |
|---|---|
| Portability | Same skill across different runtimes, tools, and model versions, with declared dependencies |
| Selection at scale | Relevant-skill coverage, selection errors, and final utility as distractor count grows |
| Composition | Joint success, conflicts, resource contention, and recovery under multi-skill tasks |
| Capability permissions | Actual side effects compared with the externally enforced allowed scope |
| Verification | Positive and negative cases, including wrong procedures, deadlocks, and boundary violations |
| Continual learning | New-task gains alongside retained performance on earlier and rare task families |
| Skill evaluation | Reuse, maintenance under environment changes, and composition quality as well as task success |

These tests should separate a bad procedure from a correct procedure that was never retrieved, a correct retrieval that was ignored, and correct execution under a defective evaluator. The survey supplies the categories; SRA-Bench, SkillsBench, and the optimizer papers in this collection provide more specific experimental patterns.

## An Everdict lifecycle with separate evidence and authority

The immediate application is a versioned artifact record: source provenance, exact content digest, declared dependencies, proposed scope, producing evidence, and evaluation outcomes. Keep a raw append-only ledger and a mutable derived summary. A driver can merge or retire advice, but cannot rewrite the evidence supporting an earlier decision.

Treat usefulness and permitted execution as separate axes. A skill can be effective within a narrow scope without receiving broader privileges; a permitted package can still be ineffective. This avoids collapsing task success, author reputation, and platform authority into one trust score.

An evolution experiment can change one dimension at a time: content, routing, composition, or environment adaptation. Freeze the baseline and the full candidate, use development evidence for curation, selection evidence for choosing, and independent confirmation for adoption. Track negative transfers and retained capability along with average improvement. The survey's governance framework is a source of testable design ideas, not a reason to replace Everdict's first-loop contract with an unvalidated four-tier mechanism.[^13]
