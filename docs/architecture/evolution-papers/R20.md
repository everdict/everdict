# R20 — Skill0: withdrawing skill context during reinforcement learning

Skill0 trains a vision-language policy with skill guidance, progressively removes that guidance, and evaluates the resulting policy without external skills. It combines reinforcement learning, a skill-withdrawal curriculum, and rendering interaction history as images to reduce context tokens. It is a model-training intervention, unlike WikiSkill's external knowledge maintenance or a frozen-model harness search. Its empirical gains are useful, but several algorithm and theory details require care before reproduction. This note follows arXiv 2604.02268v2.[^1]

## Problem and connection to surrounding research

An agent can follow a procedure placed in its prompt without learning to perform that procedure after the prompt disappears. Always supplying skills during training may create dependence; never supplying them may make exploration too difficult. Skill0 tests an intermediate approach: use guidance to reach useful behavior, then train under progressively reduced guidance.

The method builds on SkillRL's hierarchical skill bank, GRPO-style reinforcement learning, and AgentOCR's visual encoding of textual interaction history. Its comparisons also include memory-based agents, search-trained policies, and ordinary few-shot prompting. These solve related but distinct problems. Memory retrieval preserves editable external knowledge; parameter internalization changes the executable model identity and can make later corrections harder to localize.[^2]

“Zero skills at inference” means no external skill context. Search-QA still uses a retriever, ALFWorld still supplies observations and admissible actions, and all tasks still use a trained model and a harness. It does not mean zero tools, zero context, or zero task-specific training.

## Agent loop and visual context

The policy receives the task instruction and interaction history, then emits an action and a compression choice. General skills describe broadly useful strategies; task-specific files describe category procedures and applicability conditions. Examples include acquiring a required object when found, cleaning before placement, checking a configured product's price, and decomposing a multi-hop search question.[^3]

Instead of carrying all history and skills as text tokens, the method renders them as RGB images and supplies visual embeddings. ALFWorld/WebShop use 10-point monospace text and maximum width 392 pixels; Search-QA uses 12-point text and 560 pixels, with line spacing 1.2. Colors distinguish different context roles. This is optical compression of text, not a claim that the benchmark observations are intrinsically visual.

Compression trades context length against legibility. The model chooses a factor for the next image while choosing its current action. The appendices also show textual task/current-observation fields, so a low visual-context token count should not be read as the complete economic cost of rendering, encoding, generation, and environment interaction.

## Reinforcement learning objective and a notation inconsistency

For each sampled task, the current policy generates a group of trajectories. Rewards are normalized within the group to produce relative advantages. A clipped importance-ratio objective encourages actions from better trajectories while limiting the size of policy changes; a reference-policy KL term is included in the written objective. Skills affect exploration and rewards during training, and parameter updates retain behavior after the skill context is removed.[^3]

The composite reward adds a compression term only to successful trajectories. Equation 4 writes this as `lambda × ln(c)` with `c` in (0,1]. However, the implementation prompts explicitly request a compression factor greater than 1.0, with larger factors providing more compression. These definitions are inconsistent as written: `ln(c)` is nonpositive on the equation's interval, and maximizing it favors values near one. The actual factor convention and reward sign must be checked in code before implementation; silently treating the two definitions as interchangeable would change the optimization objective.

This is a documentation-level finding, not a verified bug in released training code. The reported experiments can still be evidence of an implemented method, while the printed formulas are insufficient to reconstruct that implementation unambiguously.

## Helpfulness measurement and curriculum

Before training, a validation subset removed from training data is grouped by the skill category needed for each task. Every ten training steps, the current policy is evaluated with skill context and without it. The difference in accuracy measures remaining helpfulness. Files with nonpositive helpfulness are filtered out; the rest are ranked and truncated to the current stage budget.[^4]

The budget itself is a fixed linear schedule, not entirely adaptive. With three stages, ALFWorld allows at most [6,3,0] files and Search-QA [5,3,0]. Selection within that cap is adaptive. Even a skill still helpful at the last stage is removed because the cap reaches zero. Thus “withdraw only when learned” overstates the implemented constraint.

There is also an attribution distinction. The prose describes testing one skill on its matched subtask; Algorithm 1 compares the active set with an empty set on that subtask; Appendix A defines a leave-one-skill-out marginal effect. These are three different measurements when skills overlap or interact. Reproduction needs to pin which condition is executed, because a whole-set gain cannot automatically be attributed to one file.

The intended dynamics are understandable without assuming perfect attribution. Early in training, the agent may not know how to use guidance, so the with/without gap is small. The gap rises as guidance becomes useful, then shrinks as the unguided policy improves. A small gap alone is insufficient evidence of learning: it can also occur when both conditions fail. Track absolute performance alongside the gap.

## Experimental setup and comparison boundaries

The study trains Qwen2.5-VL 3B and 7B for at most 180 steps on four H800 GPUs. ALFWorld follows GiGPO's training split, with sixteen tasks per batch, eight rollouts per prompt, and a 3,072-token maximum prompt. The benchmark contains 3,827 instances across six household task categories; that total should not be mistaken for a reported test-set size.[^5]

Search-QA follows Search-R1 with an E5 retriever, training on NQ and HotpotQA. NQ/HotpotQA are in-domain; TriviaQA, PopQA, 2Wiki, MuSiQue, and Bamboogle are out-of-domain evaluation. Search batches contain 128 tasks with a 4,096-token prompt limit. WebShop uses 1,000 training tasks, sixteen tasks per batch, eight rollouts per prompt, a 4,096-token limit, and 128 fixed validation tasks for evaluation. The general setup reports a validation subset of 1,000 and three curriculum stages; the exact per-domain membership should be checked in the released split rather than assuming the same count applies identically to every domain.

The 3B SkillRL comparison is reproduced without its cold start and skill evolution. Text baselines and visual methods also use different Qwen2.5 family variants. Extended comparison tables mix additional configurations: for example, the 7B GRPO ALFWorld score differs between the main and extended table, and Mem0's 54.7 is the RL-trained variant rather than its 33.6 untrained row. These are broader reference comparisons, not uniformly matched interventions.

## Main results: accuracy, cost, and model size

The table reports skill-free Skill0 against AgentOCR, the close visual-history RL baseline.[^6]

| Model | Task | AgentOCR | Skill0 | Skill0 context tokens/step |
|---|---|---:|---:|---:|
| 3B | ALFWorld success | 78.2% | 87.9% | 0.38k |
| 3B | Search-QA average | 34.2% | 40.8% | 0.18k |
| 3B | WebShop accuracy | 56.3% | 66.4% | 0.49k |
| 7B | ALFWorld success | 81.2% | 89.8% | 0.41k |
| 7B | Search-QA average | 40.1% | 44.4% | 0.34k |
| 7B | WebShop accuracy | 59.3% | 74.2% | 0.46k |

The 3B gains are 9.7, 6.6, and 10.1 percentage points, respectively. WebShop also reports partial-match scores: 78.6/85.1 for Skill0 3B/7B, distinct from exact success accuracy. Adding skills back at inference gives scores 80.9/85.3 but lower exact accuracy 64.1/71.9. Different metrics can favor different conditions.

Skill0 3B beats the simplified SkillRL comparison on ALFWorld 87.9 versus 82.4 and Search-QA 40.8 versus 38.9. At 7B, SkillRL remains slightly higher on ALFWorld, 89.9 versus 89.8, and higher on Search-QA, 47.1 versus 44.4. The contribution is competitive skill-free behavior with lower context overhead, not universal superiority over skill-augmented training.

Search-QA gains are uneven. Bamboogle reaches 63.7/66.9 for 3B/7B, while several other datasets remain below competing methods. The seven-dataset mean gives this small benchmark a full dataset-level contribution; a pooled question-level aggregate would answer a different question. Similarly, fewer context tokens per step does not prove lower total training cost or equal latency across text and vision pathways.

## Training dynamics and all main ablation families

Learning curves compare Skill0 with AgentOCR, GRPO, and SkillRL, and compare skill-present versus skill-absent validation. They show the unguided condition catching up during training, including category-level plots in Appendix B. This supports successful withdrawal on the tested tasks, but no mechanistic probe directly identifies a particular skill representation in model weights.[^7]

The ALFWorld budget ablations are particularly informative. Constant [6,6,6] scores 85.9 with skills but 72.6 without, a 13.3-point withdrawal loss. The proposed [6,3,0] scores 86.3 with and 87.9 without. No-skills training [0,0,0] reaches 78.9. A five-stage [6,4,2,1,0] schedule reaches only 71.1 without skills, showing that more gradual stages are not automatically better under the fixed training budget. The main plots additionally examine a static [3,3,3] budget and fixed-full unfiltered skills, the latter losing 12.3 points on withdrawal.

Removing the positivity filter gives 81.6 with skills and 78.9 without. Its 2.7-point number is the within-variant withdrawal loss; the skill-free deficit against full Skill0 is 9.0 points. Random selection without helpfulness ranking gives 76.6 with and 62.9 without, a 13.7-point withdrawal loss and a 25-point deficit against the full method. These comparisons support the tested selection protocol, rather than proving every positively scored skill is necessary.

Validation intervals of 5, 10, and 20 steps yield ALFWorld 87.5, 87.9, and 78.1. Search-QA subset results are 49.6, 48.9, and 42.3; these subset scores are not the main seven-dataset averages. Ten steps is chosen as an accuracy/overhead compromise. Training-seed confidence intervals and a full cost accounting for repeated helpfulness validation are not supplied with these tables.

## What the theory does and does not establish

Appendix A argues that a bounded reduction in skills controls reward perturbation, then relates that perturbation to normalized advantages and policy stability. It also invokes approximate submodularity for a greedy skill-selection approximation guarantee.[^8]

The first step needs an extra assumption missing from the stated cap alone. From `|active set| <= budget`, it does not follow that the number removed is at most the decrease in budget. For example, a cap changing from six to three still permits the positivity filter to remove all six. Reranking can also replace identities while the count stays fixed. A bound on actual set changes and skill influence is necessary before claiming smooth context or reward changes.

The selection guarantee likewise assumes suitable set-function properties and greedy marginal-gain selection. The printed algorithm sorts helpfulness scores once, while its score definition differs from the appendix's marginal effect. Strongly complementary procedures need not satisfy diminishing returns, and the paper does not empirically establish the required assumptions. The theory is conditional motivation, not a demonstrated guarantee for the exact published loop or for Everdict's interacting instructions.

## Everdict implications and a bounded proposal

The near-term transferable idea is to test whether a behavior still works when supporting advice is removed. For an external harness candidate, compare full advice, reduced advice, and no advice on held-out tasks, tracking both absolute success and the difference. This diagnoses dependency without claiming that a frozen model has internalized anything through gradient updates.

Actual Skill0-style internalization would be a separate model-training campaign. Its output must carry a new model/checkpoint identity, data lineage, training recipe, rendering configuration, and evaluation results. It cannot be recorded merely as a wiki edit while retaining the same executor identity. The documented first Everdict evolution loop currently emphasizes immutable external candidates; this paper motivates a later, explicitly scoped extension rather than an implicit expansion of that loop.

A useful comparison would hold the model initialization, training tasks, rollout budget, and rendering method fixed across no-skill RL, always-skill RL, fixed withdrawal, and helpfulness-ranked withdrawal. Charge paired validation calls, test genuinely held-out tasks, audit score attribution with leave-one-out checks, and retain regressions when guidance disappears. Avoid converting a low helpfulness estimate into a platform decision to delete evidence: raw traces and source procedures remain valuable even if a particular executor no longer benefits from seeing them.

## Evidence status and reading route

Read the three main task tables, Algorithm 1, Appendix C's numerical ablations, and Appendix E's prompts together. Then read Appendix A with the actual set-change and marginal-effect assumptions in view. The most defensible conclusion is empirical: guided RL with staged withdrawal can produce strong skill-free policies in the tested environments, with visual compression contributing to low context-token usage. The causal contribution of each component and the formal guarantees are narrower than the headline suggests.
