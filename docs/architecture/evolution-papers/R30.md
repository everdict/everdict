# R30 — Skill1: assigning one outcome to selection, execution, and distillation

Skill1 trains one language-model policy to retrieve and rank skills, execute a task using a skill, and distill new skills afterward. It derives the three learning signals from the environment's task outcome rather than using a separate quality judge. The idea is relevant to Everdict because a useful knowledge store requires both good entries and a good policy for finding and applying them. However, the paper's credit assignment is a proxy for future usefulness, and its reported protocol contains inconsistencies that matter for reproduction. This note follows arXiv 2605.06130v3.[^1]

## Problem and relation to neighboring approaches

A skill-augmented agent can fail at three different points: retrieving the wrong procedure, applying a good procedure incorrectly, or creating poor material for future reuse. Training only one part leaves the others as bottlenecks. Different reward sources can also disagree—for example, a judge may favor elegant summaries that do not help execution.

Skill1 uses a single Qwen2.5-7B-Instruct policy for all stages and trains its weights with reinforcement learning. A separate frozen sentence encoder provides retrieval. The external library also changes. This is joint policy-and-memory learning, distinct from WikiSkill's frozen executor and from Skill0's eventual removal of external skills. It connects to SkillRL, EvolveR, RetroAgent, and learned routing, while attempting to optimize the full selection–use–distillation lifecycle with one outcome source.[^2]

The paper models the system as a partially observable decision process. The effective state includes the task, environment, and persistent library; observations reveal only part of it. This formulation explains why the same instruction can lead to different behavior after library changes. It does not make the library's utility directly observable.

## The three-stage workflow

Each skill contains a strategy explaining how to act and a scenario description explaining when it applies. The library starts empty and is capped at 5,000 entries. For each task, the policy generates a natural-language query. A frozen all-MiniLM-L6-v2 encoder, with 384-dimensional embeddings, retrieves the five descriptions most similar to that query.[^3]

The same policy ranks those candidates by generating a permutation of their IDs. The top-ranked strategy is injected into the executor's context. The policy then interacts with the environment, using observations, a recent action history, and admissible actions. The prompts explicitly warn that past lessons can be outdated and should be used only when consistent with the current situation.

After each rollout, the policy writes a new strategy and scenario description from the task, outcome, and trajectory. The appendix expresses this as structured fields for task success, action lesson, navigation lesson, and a general description of when the lesson applies. Only successful rollouts contribute new entries. Successful episodes can contain earlier failed actions, so their distilled lessons can still describe local mistakes.

Sixteen independent rollouts per task each perform their own query, ranking, execution, and distillation. When capacity is reached, an entry is retired using the lowest `U(s) × log n(s)`, where U is utility and n is selection count. The intended preference is for well-tested, useful skills. Initialization and zero-count handling are not fully specified in the equations; `log 0` and the empty-library maximum need explicit implementation choices.

## One outcome, three reward signals

The environment supplies a terminal binary outcome r. Execution receives r directly. Query generation is part of the prefix that leads to the execution and receives policy gradients from the same utilization objective.[^4]

For each retrieved skill, the system maintains an exponential moving average:

`U(s) ← (1 − α)U(s) + αr`, with `α = 0.05`.

Crucially, it updates all five retrieved candidates, including the four that were not selected. The authors treat co-retrieval as evidence about the same task distribution. This smooths noisy episode results, but it does not measure each candidate's causal contribution: an unused or irrelevant skill can inherit credit from a successful executor or another skill. The utility is therefore a retrieval-associated success statistic, not a counterfactual skill-effect estimate.

Ranking receives NDCG agreement with the utility-based ordering. NDCG rewards placing higher-utility entries near the top; it aligns the generated permutation with historical scores. This provides a learnable preference, but its validity depends on the utility estimate and cannot independently verify relevance.

Distillation receives `r − max U(s)` over retrieved candidates. A successful task with a low-utility neighborhood has high residual reward, while failure has non-positive residual. The authors call the moving average a low-frequency trend and the residual a high-frequency variation. This is a temporal smoothing metaphor, not a spectral decomposition or a theorem establishing novelty.

The important limitation is timing: r is determined before the new skill is written. The reward can identify potentially informative experience, but does not test whether the generated wording helps a future task. Alternative summaries of the same fixed trajectory receive the same scalar proxy. Moreover, for bounded utilities, a successful duplicate can still receive positive reward; a negative residual is not a direct detector of redundancy. Claims that the method specifically rewards genuinely novel skills are stronger than the formula alone establishes.

## Joint optimization and protocol inconsistencies

Utilization/query tokens and distillation tokens use separately normalized group-relative advantages and clipped GRPO objectives. A KL term constrains departure from a reference policy. Ranking instead uses a REINFORCE-style log-probability objective weighted by its NDCG reward, because candidate sets differ across rollouts. The total combines utilization with ranking and distillation weights both 0.3.[^5]

The training configuration uses learning rate 10^-6, KL coefficient 0.01, BF16 FSDP on eight H800 80GB GPUs, and vLLM tensor parallelism four. Prompt and response limits are 16,384 and 2,048 tokens. ALFWorld uses a task batch of sixteen and at most fifty environment steps; WebShop uses 32 and at most fifteen. Validation temperature is 0.4. The infrastructure section describes convergence in 100–150 steps and roughly thirty hours on ALFWorld.

Several details need resolution before reproduction. Algorithm 1 prints `−αU + αr` in its utility update, whereas Equation 5 correctly specifies `(1−α)U + αr`. The configuration table lists UCB selection during training, greedy selection during evaluation, exploration scale 1.0, and similarity weight 0.6, while the main method describes a learned query and permutation policy. Their exact interaction is not explained. The appendix also calls the shared budget 150 epochs, in tension with the step-based convergence description.

These are reporting inconsistencies, not verified defects in the implementation. The paper names benchmark train/test splits but does not provide a complete task-ID manifest or equally detailed test-library reset/update policy in these sections. The exact evaluated task population and library state should be recovered from code before claiming replication.

## Main task results and baseline provenance

| Method | ALFWorld reported aggregate success | WebShop score | WebShop success |
|---|---:|---:|---:|
| ReAct, no training | 31.2% | 46.2 | 19.5% |
| GRPO, no skills | 77.6% | 79.3 | 66.1% |
| GiGPO, no skills | 90.8% | 84.4 | 72.8% |
| SkillRL | 89.9% | 85.2 | 72.7% |
| RetroAgent | 94.9% | 88.9 | 82.3% |
| Skill1 | 97.5% | 89.7 | 82.9% |

Skill1's ALFWorld gain over RetroAgent is 2.6 percentage points; WebShop success improves only 0.6 points. WebShop score and strict success are different metrics and should remain separate. Skill1 leads in five of six ALFWorld categories but loses on Clean: 97.3% versus RetroAgent 99.2%.[^6]

The paper reproduces RetroAgent with its official implementation, while many other baselines are borrowed from prior papers under the same base model. Its assertion of identical budgets does not establish identical executed conditions for every imported result. Comparing the table's trained and untrained rows also mixes much more than the presence of a library.

The reported ALFWorld aggregate is 97.5%, whereas the simple mean of Skill1's six printed category scores is approximately 97.87%. The aggregate should therefore not be called a six-category macro-average without clarifying weighting. Exact task counts and aggregation are necessary for reproducing that number.

## Ablations: what helps and what remains confounded

Removing the library reduces ALFWorld success to 80.9%. Removing selection yields 91.8%; removing distillation yields 92.4%. The latter stores raw trajectories instead of condensed skills, so it changes representation length and content as well as the distillation operation.[^7]

Keeping the workflow but setting the ranking weight to zero yields 94.0%; setting the distillation weight to zero yields 94.9%; removing both auxiliary losses yields 90.2%. These comparisons support the value of the full training configuration on this environment. The joint effect is not additive, and individual categories can improve when a component is removed—for example, Clean is 98.8% without the ranking objective, above the full model's 97.3%.

The no-library variant is not simply the original GRPO table row: it scores 80.9% versus 77.6%. Treat each as a separate reported configuration. The ablations do not isolate how much improvement comes from better weights, a better library, or better matching between them; swapping frozen components at evaluation would help answer that question.

## Training dynamics, diversity, and statistical evidence

The authors track utilization reward, a selection metric based on utility, and a distillation-positive rate. Selection reaches about 0.95 by step twenty; utilization and distillation reach about 0.8 by step sixty. Task–skill similarity rises from 0.51 to 0.60, and top-skill utility reaches about 0.91 by step 85. Ablated systems lag.[^7]

These measurements are coupled to the same outcomes used for training. Rising utility can reflect a stronger executor or easier retrieved tasks, not only better stored skills. The dynamics prose also describes the distillation baseline as an average in one place, whereas the formal reward uses the maximum. The curves therefore should not be read as independent validation of three separately measured causal abilities.

A t-SNE plot and usage visualization suggest broader activation of the library, with nearly twice as many highlighted frequently used skills. A two-dimensional embedding picture does not establish coverage of all useful strategies; cardinality, projection settings, and semantic audits matter. No controlled duplicate-insertion or rare-skill-retention experiment establishes the eviction policy's behavior.

The three-seed aggregate comparison reports Skill1 97.5 ± 0.6 versus RetroAgent 94.9 ± 0.9, with Welch's t-test p=0.021. The Clean difference has p=0.147. These are small-seed statistical results, not proof of zero seed sensitivity or equality on Clean. Category tests also require attention to multiple comparisons. The appendix's broad statement about running all methods with three seeds should be read alongside its explicit borrowed-baseline description.

## Compute and qualitative cases

At steps twenty, sixty, and one hundred, Skill1 takes 386.6, 444.3, and 493.8 seconds per training step, versus no-library GRPO 301.3, 274.1, and 296.7. Its library grows through 915, 3,899, and 5,000 entries. The raw-trajectory variant is much slower at later checkpoints: 750.1 seconds at step sixty and 738.4 at step one hundred.[^8]

These measurements show that skill management is not free. They are training-step costs, not inference latency or cost per accepted production task. The paper attributes growth partly to longer selection context, but top-five retrieval is fixed; entry length and implementation details are needed to explain why library cardinality changes context. The SkillRL cost row appears experimentally measured although its main score is described as borrowed, so score/cost comparability also needs verification.

Two case studies show reuse of a microwave-heating lesson and correct object targeting under a desk lamp. They make the intended mechanism concrete: transfer an appliance constraint across destination changes and avoid a previously observed targeting error. However, skills still include instance-specific locations, and the examples are selected successes rather than a randomized estimate of transfer reliability. Current observations must override stale locations.

## An Everdict design derived from Skill1

First separate library quality, retrieval quality, and executor competence in evaluation. Freeze an executor and compare the same candidate library under different selectors; then freeze selection and swap libraries. A final crossed test can measure their interaction. This is a proposed Everdict experiment, not an implemented change or an experiment already supplied by Skill1.

Maintain retrieval-associated utility as advisory evidence with task-family, executor-version, and sample-count provenance. Do not call it causal skill utility or let it authorize adoption. For selected skills, occasionally run budgeted matched no-skill or alternative-skill trials on development tasks. Evaluate newly distilled text on later, separated tasks before assigning confirmed value.

Preserve raw trajectories even when the curated projection replaces them. Keep rare, low-count skills distinguishable from repeatedly tested failures, and define cold-start and zero-count behavior explicitly. Selection can guide the next experiment; confirmation should still use frozen baselines, immutable candidate bytes, and undisclosed task families. Skill1's most useful idea is lifecycle-aware credit assignment, while its proxy rewards show why Everdict needs stronger evidence before promoting a memory change.
