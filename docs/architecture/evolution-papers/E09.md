# E09 — ReasoningBank: Scaling Agent Self-Evolving with Reasoning Memory

## Reading guide and evidence scope

Ouyang et al., **2509.25140v2**, studies learning from a stream of tasks by storing distilled reasoning advice with a frozen language model. The main text, all appendices, result figures, and extraction/judging/scaling prompts were inspected. The work includes WebArena, Mind2Web, SWE-bench Verified, and a smaller-model extension. This review did not reproduce the experiments.[^1]

The key proposal is to learn **different kinds of lessons from successes and failures**, then use additional attempts on a task to improve the memories available for later tasks. For Everdict, this suggests keeping failure evidence and testing contrastive reflection, while keeping inferred advice distinct from verified outcome evidence.

## Background: memory content versus memory infrastructure

A raw trajectory preserves detail but may be long and tied to a particular page or identifier. A workflow abstracts a successful sequence into a reusable procedure. ReasoningBank instead asks for a short explanation of a reasoning strategy: why to inspect all pages before reporting completeness, when to use category filters, or why an apparently relevant result may not satisfy the task.

The paper compares this content with trajectory memory **Synapse** and workflow memory **AWM**, while giving the baselines the same retrieval and consolidation mechanisms. Thus the comparison isolates a family of memory-extraction choices more closely than it compares complete original implementations of every memory system. Most baseline memory comes from self-judged successful trajectories; a later ablation also permits failures.[^2]

Unlike [Reflexion](E01.md), the main emphasis is reuse across a stream of different tasks, rather than just retrying one failed task. Unlike [ACE](E08.md), ReasoningBank does not maintain a large globally injected playbook with deduplication. It retrieves a small group of memories associated with a similar previous query. Unlike a learned router or curator such as [SkillOS](R24.md), it does not train new model weights.

## Representation, retrieval, and update loop

Memory starts empty. Each stored JSON experience contains the **task query, original trajectory, and associated memory items**. An item has a title, a one-sentence description, and content. The extraction prompt permits at most three items per trajectory, with content usually one to three sentences, and asks the model to avoid specific websites, query strings, and redundant items.[^3]

For a new query, `gemini-embedding-001` embeds the query. Cosine similarity retrieves the most similar **previous experiences**, default **one experience**, and all its associated items are inserted into the agent’s system prompt using title and content. “Top-1” therefore does not necessarily mean one bullet. Retrieval is based on stored query embeddings, not a demonstrated learned causal relevance score over individual memory statements. The agent is instructed at each step to consider whether each memory is relevant before acting.

After the task finishes, the same backbone model acts as a binary success/failure judge, at temperature 0.0. The judge sees the user’s intent, trajectory, final webpage state, and response; it does not receive the benchmark’s reference answer in the ordinary adaptation loop. A same-backbone extractor at temperature 1.0 then uses a success-specific or failure-specific prompt. New entries are **appended without pruning, merging, or forgetting**. Temperature zero reduces sampling variation but does not make a remote model perfectly deterministic or its judgment correct.

The paper uses the agent’s intermediate reasoning as an approximation to lengthy observation histories in memory processing. This saves context, but a generated narrative is not equivalent to the complete observed environment. The storage schema retains what the implementation calls the original trajectory; exact observation retention matters for auditing.

Successful memories are called validated strategies in the paper, but validation here usually means an LLM judged the trajectory successful. Likewise, a failed trace can suggest a counterfactual correction without actually testing that correction. These are useful hypotheses, not automatically causal facts. A false diagnosis can be retrieved repeatedly because it remains textually relevant.

## Memory-aware test-time scaling: what the additional compute does

**MaTTS** adds more experience per current task, then uses it to improve later memory. It has two forms.[^4]

In **parallel scaling**, the agent produces `k` trajectories for the same query using existing memory. Instead of independently extracting a memory from each, a single contrastive extraction considers the trajectories together: which choices recur in successful paths, which mistakes explain failed paths, and which principles generalize. Its prompt permits at most **five combined items**, with content up to five sentences. This differs in both evidence and output budget from the default three-items-per-trajectory extraction.

In **sequential scaling**, the agent revisits one trajectory after an initial completion. A first checking instruction asks it to reexamine selected elements and whether the answer satisfies the query; later instructions ask it to check again. Intermediate corrections become evidence for memory extraction. These are additional within-task checks, not additional independent tasks or weight updates. The paper uses `k` as its scaling factor, with `k=1` denoting the unscaled condition.

Three result concepts must remain separate:

- **Pass@1 in the parallel study:** score one randomly selected trajectory from the `k` generated attempts. Memory was still accumulated using the more expensive multi-attempt procedure on the task stream. This is not the total cost of a one-attempt system.
- **Best-of-N (BoN):** the same backbone LLM sees candidate trajectories and selects one. This is a fallible learned selector, not an oracle choosing whichever attempt actually passed.
- **Pass@k:** count whether any of the `k` attempts succeeds under the benchmark evaluator. This measures available solution coverage, not the success of an executable selector.

The BoN prompt evaluates progress, efficiency, loops, errors, and coherent planning from action/reasoning traces. Plausible explanations can influence it. For state-changing tasks, selecting a transcript also does not by itself undo the other attempts’ side effects; isolated environments and the final state-selection protocol need to be explicit in a reproduction or deployment.

## WebArena: task scope and main results

WebArena uses live benchmark environments and a ReAct-style BrowserGym agent with text accessibility-tree observations, temperature 0.7, and at most **30 interaction steps per query**. The map domain is excluded because of website issues. The evaluated **684 tasks** comprise shopping 187, administration 182, GitLab 180, Reddit 106, and multi-site 29. Final success is measured with the benchmark’s ground-truth evaluator, separately from the self-judge used to learn memories.[^5]

| Backbone and method | Overall success | Mean interaction steps |
| --- | --- | --- |
| Gemini 2.5 Flash, no memory | 40.5 | 9.7 |
| Flash, Synapse / AWM | 42.1 / 44.1 | 9.2 / 9.0 |
| Flash, ReasoningBank | 48.8 | 8.3 |
| Flash, ReasoningBank + parallel MaTTS, k=5 | 51.8 | 7.9 |
| Gemini 2.5 Pro, no memory | 46.7 | 8.8 |
| Pro, Synapse / AWM | 47.7 / 47.6 | 8.5 / 8.7 |
| Pro, ReasoningBank | 53.9 | 7.4 |
| Pro, ReasoningBank + MaTTS | 56.3 | 7.1 |
| Claude 3.7 Sonnet, no memory | 41.7 | 8.0 |
| Sonnet, Synapse / AWM | 42.6 / 40.8 | 7.9 / 8.9 |
| Sonnet, ReasoningBank | 46.3 | 7.3 |
| Sonnet, ReasoningBank + MaTTS | 48.8 | 7.2 |

ReasoningBank gains **8.3, 7.2, and 4.6 percentage points** over the corresponding no-memory agents. Flash’s 8.3/40.5 is about **20.5% relative**, explaining the headline “up to 20%”; it is not 20 percentage points. Pro’s step reduction 8.8→7.4 is about 15.9%. The MaTTS rows use the paper’s parallel pass@1 convention, so the shown steps do not include the total interactions across all five attempts plus extraction and selection.

ReasoningBank improves success over no memory on each reported domain/backbone cell. The multi-site results are small in absolute counts: Flash and Pro reach 13.8% on 29 tasks, about four successes, and Sonnet 3.4%, about one. This is useful evidence of cross-site reuse but carries much more sampling uncertainty than a large held-out transfer study. Mean interactions sometimes increase for an individual domain when MaTTS is added, even though the overall average decreases.

## Mind2Web and software engineering

Mind2Web has **1,341 tasks**, divided into cross-task 252, cross-website 177, and cross-domain 912. Each task has a prescribed sequence of steps. The model predicts an element and action at each step; the benchmark reports element accuracy, action F1, step success requiring both, and task success requiring **every step** to succeed. These are not interchangeable with online WebArena end-state completion.[^5]

| Backbone / split | No-memory step success → ReasoningBank | No-memory full-task success → ReasoningBank |
| --- | --- | --- |
| Flash, cross-task | 40.3 → 44.9 | 3.3 → 4.8 |
| Flash, cross-website | 31.7 → 33.9 | 1.7 → 2.3 |
| Flash, cross-domain | 31.9 → 36.6 | 1.0 → 1.6 |
| Pro, cross-task | 44.4 → 45.6 | 3.5 → 5.1 |
| Pro, cross-website | 34.8 → 36.9 | 3.4 → 3.8 |
| Pro, cross-domain | 35.0 → 38.1 | 1.4 → 1.7 |

Element accuracy and action F1 also improve in all six base comparisons; for example Flash cross-domain is 35.8→40.6 and 37.9→41.3 respectively. ReasoningBank beats the listed memory baselines on the reported task-success cells, but absolute full-task success remains low. A 60% relative gain from 1.0 to 1.6 is only 0.6 percentage points. The evaluation is still a test-time learning stream, not necessarily a frozen memory tested on a permanently unseen domain: the exact reset and task-order manifest matters when interpreting cross-domain transfer.

On **all 500 SWE-bench Verified tasks**, a minimal Bash-based ReAct scaffold produces patches evaluated with official tests. Flash improves from **34.2 to 38.8 resolved**, with mean steps **30.3→27.5**; Pro improves **54.0→57.4**, steps **21.1→19.8**. Synapse is 35.4 and 53.4. AWM is omitted because the authors consider its workflow representation difficult to apply to arbitrary Bash commands; that is an experimental choice, not proof that workflow memory cannot support code agents. MaTTS is not reported as a full SWE experiment here. The paper discusses patch application as a metric but does not provide a separate main-table application-rate result.

## Scaling experiments and the memory–compute interaction

Detailed scaling studies use **WebArena-Shopping with Gemini 2.5 Flash**, not every dataset. Parallel MaTTS BoN rises from **49.7 at k=1 to 55.1 at k=5**, compared with 52.4 for independent memory extraction without aggregation and 42.2 without memory. Sequential MaTTS reaches **54.5**, versus 51.9 without aggregation and 40.6 without memory. Sequential has a small advantage at lower `k`, while parallel is slightly ahead at five; there are no broad uncertainty estimates proving a universal crossover.[^4]

At `k=5`, ReasoningBank’s randomly selected trajectory scores **53.0**, compared with unscaled 49.7. Synapse moves 40.6→41.2 and AWM 44.4→45.5; the text says scaling “reduces” performance for weaker memories while the displayed numbers actually increase. The justified conclusion is smaller improvement, not regression.

Oracle pass@5 reaches **62.1** for MaTTS, versus 56.1 without aggregation and 52.4 without memory. The gap between 62.1 oracle coverage and 55.1 learned-selection success reveals remaining selection difficulty. It is not additional performance that a deployed agent can claim automatically. Because each setting also creates a different subsequent memory stream, these results combine better exploration, different memory content, and downstream effects; they are not simply five independent samples from one permanently frozen policy.

## Ablations, judge calibration, efficiency, and case studies

**Learning from failure.** On Shopping, ReasoningBank is **46.5 with success-only memory → 49.7 with successes and failures**. Synapse moves 40.6→41.7, while AWM drops 44.4→42.2. The extraction representation determines whether failure traces become useful advice or confusing examples. Failure memory is beneficial in this setting; the experiment does not prove every inferred failure cause is correct.[^6]

**Retrieval quantity.** Zero/one/two/three/four retrieved experiences yield **39.0/49.7/46.0/45.5/44.4**. One relevant experience outperforms more context here. This complements ACE’s result: preserving a rich store and injecting many entries into every task are different decisions.

**Judge quality.** The Flash judge agrees with Shopping ground truth **72.7%** of the time. To vary accuracy, the authors replace labels with ground-truth labels flipped at controlled probabilities. At simulated 100/90/80/70/60/50% accuracy, task success is **52.4/49.7/48.7/49.7/47.6/47.6**. This uses ground truth for an analysis intervention, not ordinary label-free learning. Random independent label flips differ from systematic false positives on one dangerous failure type. Overall agreement alone does not provide precision, recall, or calibration by task difficulty.

**Interaction efficiency by outcome.** On successful Shopping tasks, mean steps fall **6.8→4.7**; failed tasks fall 8.7→7.3. Similar, smaller reductions appear in administration, GitLab, and Reddit. The text calls the 2.1-step successful-case reduction 26.9%, but the table gives about **30.9%**. More importantly, methods solve different sets of tasks, so conditioning separately on success does not create a paired same-task causal comparison. It supports an efficiency pattern without proving its entire mechanism.

**Total token accounting.** Per-task action-generation tokens fall from **50,847.4 to 49,306.1**, but judging adds 2,186.3 and extraction 1,562.1, making the total **53,054.5**, about **4.3% above no memory**. Synapse and AWM total 58,514.7 and 59,372.8. These are token counts, not billed dollars, wall-clock time, or a complete `k=5` MaTTS cost analysis. Embedding, storage, and cache effects are not fully priced.

**Smaller model.** On Shopping, Gemma-3-12B improves **17.1→24.1**, and steps **13.7→11.8**. Synapse is 16.0 and AWM 21.4. This extends the effect to one smaller model/domain, not every low-capability agent.

**Qualitative cases.** Memories help inspect full order history rather than recent orders, reduce a shopping navigation example from 29 to 10 steps, and identify overly broad search terms and missing filters. Figure 6 illustrates a progression from finding links to checking identifiers, completeness, and task constraints. Because consolidation only appends, this is not evidence that a single stored item was mechanically revised through a verified lineage. Selected examples do not establish autonomous emergence of a new general reasoning faculty. Figure 1 plots cumulative **numbers of successes**, which can rise even if the success rate is flat.

## Limitations and concrete Everdict implications

The experiments support structured experience extraction, failure reuse, and contrastive memory formation. They leave several questions open: performance over much longer streams, task-order variance, systematic judge errors, conflicting memories, forgetting, learned retrieval, and full cost-matched comparisons. The paper itself lists composition-aware retrieval, layered memory, and merging/forgetting as future work.[^7]

For Everdict, retain raw round evidence and derive separately versioned memory entries. A useful entry should link its claim to the task, candidate digest, observed outcome, judge identity, and whether the outcome was platform-verified or inferred. An LLM’s diagnosis belongs in an advice field with provenance; it must not replace the recorded result or become promotion authority.

A concrete experiment can compare success-only extraction, success-plus-failure extraction, and contrastive extraction from an equal-budget group of attempts. Use identical retrieval, evidence access, and executor limits across arms. Track not only success but repeat failures, unsupported diagnoses, retrieval relevance, and total learning/inference cost. Compare multiple attempts on one task with the same budget spread across more tasks, because MaTTS’s “deeper experience” choice has an opportunity cost.

Retrieve small, scoped sets rather than automatically injecting the entire archive. Test per-experience retrieval against item-level retrieval and complementarity-aware selection; the paper’s top-1 result is a starting hypothesis, not a universal constant. Add a correction test in which an early plausible rule is contradicted by later evidence. Plain append-only memory cannot demonstrate that it has retracted the rule, even though the source ledger should remain append-only.

Finally, report frozen-artifact confirmation separately from online adaptation. A memory stream that has learned from earlier evaluation tasks is not an untouched confirmation run. Under the [first-loop proposal](../evolution-first-loop.md), the driver may choose curation and retrieval policies, while the platform owns disclosure, immutable artifacts, task-family confirmation accounting, and final adoption.
