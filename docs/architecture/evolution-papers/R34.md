# R34 — SkillGrad: contrastive evidence and textual momentum for skill edits

SkillGrad v1 optimizes an external spreadsheet skill while keeping model weights fixed. It repeatedly executes a small batch, diagnoses failures and recovered successes, maintains a record of recurring patterns, and edits a structured skill package. Its strongest contribution is a concrete account of what an evolution loop should remember and where a learned procedure should live. “Gradient” and “momentum” are operational analogies, not numerical derivatives or convergence guarantees.[^1]

## Motivation and relation to earlier optimizers

A failed workbook can reveal a missing rule, but a successful workbook can also teach something: perhaps the agent inspected destination headers before writing, whereas the original failed run assumed a layout. Discarding every success would discard evidence about behaviors worth preserving.

EvoSkill supplies the failure-analysis and candidate-selection comparison. Trace2Skill supplies the offline distillation comparison, where an initial trajectory pool is consolidated into skills. SkillGrad instead changes the skill after each batch, so subsequent evidence comes from a different artifact. TextGrad provides the analogy of textual error signals; SkillGrad adds a structured file package and cross-iteration pattern state. Systems such as Memento-Skills and CoEvoSkills address broader libraries or verifier-guided construction. The present experiment optimizes one spreadsheet-centered package, not a lifelong open-world library.[^1]

## What is optimized: metadata, body, and conditional resources

The parameter is a package S = (H, B, Q): metadata H, the main `SKILL.md` body B, and conditional resources Q. Metadata tells the executor when a skill is relevant. Once activated, the body remains in context; referenced material is loaded only when requested. In these experiments, learned resources are Markdown files under `references/`, rather than a separately trained collection of executable tools.[^2]

Placement is part of the update. Broad inspection and verification rules belong in the body. A longer algorithm for duplicate keys or formula-backed cells can live in a reference, linked by a factual trigger and a nearby condition under which it should be skipped. Moving everything out of the body risks non-discovery; putting everything into it burdens unrelated tasks.

The executor prompt requires activation before coding and requires reading references when a matching pointer applies. This is a strongly scaffolded loading policy, not a neutral test of whether a general agent spontaneously discovers a skill. The learned metadata's effect on open-library retrieval is not separately measured.

## From outcomes to diagnoses and momentum

For a task, the terminal loss is one minus its binary success indicator. SkillGrad supplements that sparse value with trajectories. All training tasks are sampled from failures of the initialization. If the current skill still fails, diagnosis uses its failed trace and evaluator feedback. If it succeeds, diagnosis compares the current success with the original failure on the same task.[^2]

The failure diagnoser examines cell-level discrepancies and the code or workflow that produced them. The contrastive diagnoser asks what changed and whether the successful method seems reusable or lucky. Both produce a general error or knowledge label and explanatory prose. They are asked to diagnose behavior rather than directly prescribe document edits.

Comparing the same task is more informative than comparing unrelated successes and failures, but it is not a controlled causal intervention on one skill sentence. Sampling variation and several accumulated edits can explain the difference. Even the initial unmodified skill can succeed on a new stochastic attempt after failing during screening. The diagnosis is an evidence-grounded hypothesis, not proof of the cause.

Momentum stores recurring semantic patterns rather than adding numerical vectors. Each entry tracks a pattern ID, operation/workflow type, anchor in the skill, iterations where it appeared, an evolving description, the latest recommended action, and an append-only remedy log. A batch overlay points from each task to the corresponding pattern and current gap. Raw diagnoses and linked traces remain available when compression loses detail.[^3]

Matching requires the same decision rule and corrective action; sharing a vague word such as “verify” is insufficient. The prompt favors merging rare instances into broader patterns, but permits separation where operations differ. A workflow theme needs two supporting successes in the current batch or one current and one earlier supporting entry. Unactionable evidence may receive an explicit no-signal entry instead of an invented patch.

This state distinguishes absent guidance, vague guidance, and guidance that already exists but is ignored. Repeated failure after two similar repairs can motivate changing structure or moving a branched procedure into a reference. Unlike classical momentum, there is no arithmetic decay coefficient or proven smoothing property.

## How the patcher changes the artifact

The patcher groups evidence by pattern and edits once per pattern. It considers alternative repairs, reads previous remedies, and preserves existing useful content. The prompt discourages wholesale rewriting and repeated one-off bullets. Its structural targets include a metadata description of at most fifty words, a small number of workflow and operation sections, and references with runnable example code, a branch, and a verification step that specifies corrective action.[^3]

Reference links and files must change together. Each reference should have a body pointer; missing targets and orphan references are repaired during read-back. These are authoring instructions to the LLM, not evidence of an independently enforced validator. The final read-back is explicitly lightweight, and there is no per-iteration held-out acceptance gate for SkillGrad.

Some prompt and artifact details should not transfer unchanged. The patcher prioritizes artifact-observed output categories over later wording in the task. That may address particular benchmark ambiguities, but Everdict must preserve explicit user requirements. Similarly, replacing formulas with literal values can satisfy a value-based grader while violating a requirement for a live workbook. An optimized excerpt suggests that worksheet row operations automatically rebase formulas; that is not a general property of openpyxl, whose documentation says insertion/deletion does not manage formula dependencies. Learned instructions still need contract and implementation checks.[^4]

## Data splits, model roles, and search budget

The canonical SpreadsheetBench Verified split uses 200 training candidates, twenty validation tasks, 120 test tasks, and sixty unused held-out tasks. EvoSkill alone uses the twenty-task validation set for selection. The test set is fixed across methods. WikiTableQuestions transfer uses a fixed seventy-example sample, with denotation accuracy.[^5]

For each backbone and initialization, the initial skill runs on all 200 candidates. Failure pools contain 76 and 117 tasks for the LLM-generated skill with GPT-5.4 and GPT-4.1, and 72 and 124 for the third-party skill. Each of three training-selection seeds samples forty failures. SkillGrad processes batches of four for ten updates, one pass through those forty tasks. Each execution has at most thirty agent turns.

One backbone supplies every agent role within a run: executor, diagnoser, momentum writer, and patcher. The results therefore compare complete optimizers using either GPT-5.4 or GPT-4.1, not a weak executor secretly coached by a stronger model. Model weights are not fine-tuned.

The baselines are adapted to the same initial skill, selected training tasks, backbone, and test split. This improves comparability, but does not reproduce every original paper's best search protocol or establish equal total API spending. Spreadsheet scoring recalculates formulas and requires every annotated output cell to match; the paper reports hard accuracy. The split description does not give a full public lineage audit for related instruction variants, so disjoint task IDs should not automatically be elevated to proven family-level independence.

## Main results and what the gains establish

The following table preserves all SkillGrad outcomes and the strongest adapted competitor in each block. Training-based values are means over three training-set-selection seeds; the paired columns show SpreadsheetBench / WikiTQ percentages.[^6]

| Backbone and initialization | Initial skill | SkillGrad | Best competitor on each dataset |
|---|---:|---:|---:|
| GPT-5.4, LLM-generated | 55.83 / 77.14 | 71.11 / 82.38 | 68.06 EvoSkill / 79.05 Trace2Skill |
| GPT-5.4, third-party | 60.00 / 78.57 | 69.44 / 83.34 | 63.89 Trace2Skill / 81.91 Trace2Skill |
| GPT-4.1, LLM-generated | 36.67 / 48.58 | 54.17 / 73.65 | 37.22 tied / 60.00 Trace2Skill |
| GPT-4.1, third-party | 33.33 / 42.86 | 45.83 / 53.81 | 38.89 Trace2Skill / 51.43 Trace2Skill |

The no-skill baselines are 62.50/78.57 for GPT-5.4 and 44.17/52.86 for GPT-4.1. Both initializations often hurt relative to no skill, particularly GPT-4.1. SkillGrad improves every reported block and exceeds the no-skill baseline, although third-party GPT-4.1's WikiTQ gain over no skill is only 0.95 points.

For LLM-generated GPT-5.4, the reported 4.44-point advantage is over the average of two competitors; the advantage over the stronger EvoSkill result is 3.05 points. The corresponding SkillGrad standard deviations are 1.73 points on spreadsheets and 1.78 on WikiTQ. GPT-4.1 gives 3.54 and 2.50. These are variation across three training selections, not confidence intervals over all possible task populations.

WikiTQ provides transfer to a different format and output space, but still concerns tables. It supports reusable table-handling procedures more directly than generalization to web automation, repository maintenance, or arbitrary domains. The seventy-example evaluation is small, and there is no independent reproduction in this note.

## Component ablations and budget sensitivity

On GPT-5.4 with a single fixed training seed, full SkillGrad scores 72.50%, no momentum 65.83%, and failure-only diagnosis 68.33%. These correspond to 87, 79, and 82 solved tasks out of 120. Momentum and contrastive evidence both help in this run; the ablations do not establish the same effect size across seeds, models, and domains.[^7]

Artifact inspection suggests different organization. Without momentum, the always-loaded body has 2,416 words versus 1,863 for the full method, while references contain fewer words. Failure-only diagnosis leaves five operation patterns and no workflow patterns; the full run records nine operation and two workflow patterns. This is descriptive support for the proposed mechanism, not a separately randomized test of structure or an independently validated classification of every pattern.

Batch-size analysis holds ten updates fixed. Batches of two, four, and six yield 70.0%, 72.5%, and 70.8%. They consume twenty, forty, and sixty trajectory slots, respectively; the largest setting repeats tasks from the forty-task pool. Consequently, batch size, evidence volume, and reuse change together.

Checkpoint accuracy is 63.3% at update one, 65.8% at four, 67.5% at seven, 72.5% at ten, and 70.0% at thirteen. More editing is not monotonic improvement. The authors report the fixed ten-update artifact rather than selecting the best checkpoint for each run. However, these hyperparameter plots inspect the test set, so future decisions informed by them should use a fresh confirmation set rather than call it untouched.

## Resource usage, artifact growth, and cost

The three main GPT-5.4 runs load learned references on 259 of 360 test task-runs, or 71.9%, with 267 reads. The third-party initial skill loads its general references on 113 of 120 tasks, or 94.2%. A higher activation rate is not automatically better.[^8]

Different seeds discover different organizations. One creates mapping-shape and formula-versus-Python references, read forty and thirty-eight times. Another creates a broad non-target-change check, read 119 times. A third distributes work across formula compatibility, repeated keys, and formula-backed cells. The hierarchy is exercised at evaluation, but no matched flattening or no-L3 ablation isolates its causal contribution.

Across three seeds, the body grows from forty lines to roughly 120 at the first update and ends near 154 lines; conditional resources grow to about thirteen thousand characters. Tracked patterns level near ten around iteration seven. The initial patch adds roughly 1,170 words, while later updates average about 330 additions. These are descriptive artifact statistics, not convergence or guaranteed bounded-memory results.

The ten-update API cost is $6.40 ± $0.38 for GPT-5.4, increasing from roughly $0.35 to $0.85 per iteration as skill and momentum prompts grow. This accounting covers the logged training stages. It should not be treated as a complete project bill including the initial 200-task screening, all held-out evaluations, baseline runs, and hyperparameter studies.[^8]

## Changes worth testing in Everdict

The closest fit is a driver-owned pattern record over the immutable round ledger. Each proposed lesson should link the failure or recovery evidence, identify the candidate digest, distinguish operation rules from workflow habits, and record prior attempted remedies. The current recommendation can be rewritten while the raw evidence and remedy history remain preserved. A compact overlay can direct attention without denying access to original traces.

An initial experiment should compare failure-only curation, failure-plus-recovery curation, and the same evidence with persistent pattern tracking, under matched execution and token budgets. Hold the candidate edit surface constant. A separate experiment can compare a flat artifact with a body/reference hierarchy and measure both success and retrieval cost. This avoids attributing every gain to “momentum” when content size or routing also changed.

SkillGrad's lack of a per-update gate is a search choice, not a reason to weaken Everdict's adoption contract. Exploratory descendants may regress or recover; adoption still needs frozen bytes and permitted selection/confirmation evidence. The platform owns that evidence integrity, while the driver owns semantic grouping, patch proposals, and derived wiki maintenance. This remains a proposed evolution design, not a feature already implemented by this documentation.[^9]
