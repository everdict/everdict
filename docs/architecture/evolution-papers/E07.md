# E07 — AlphaEvolve: A coding agent for scientific and algorithmic discovery

## Reading guide and evidence scope

Novikov et al., **2506.13131v1**, is a white paper about evolving programs with frozen Gemini models and executable evaluation. Its scope spans matrix multiplication, extremal mathematics, and four engineering applications. The main text, both appendices, scientific result and ablation figures, and selected verification functions in the authors’ companion notebook were inspected. The notebook snapshot is **January 5, 2026**, later than the paper; differences are identified below. Neither searches nor certificates were independently executed for this review.[^1][^8]

The central contribution is a reusable search system that lets language models propose substantial code changes while an external evaluator determines progress. It does not establish that arbitrary agents can safely rewrite their own evaluator, that model weights improve, or that fewer arithmetic operations always produce faster software. For Everdict, the strongest connection is the combination of a diverse candidate archive with a trustworthy, separately owned evaluation contract.

## Problem, prerequisites, and relation to earlier work

A language model can suggest a promising algorithm without knowing whether it works. Evolutionary search turns this weakness into repeated proposal and measurement: retain useful candidates, derive new ones, and continue until a budget is exhausted. A candidate may encode a mathematical object, a constructor for objects, or a search algorithm that discovers objects. These are different optimization targets. Finding one excellent configuration does not automatically produce an optimizer that performs well from arbitrary fresh initial states.

[FunSearch](E12.md) established this pattern for short functions. AlphaEvolve expands the editable scope to multiple functions, entire files, and languages including Python, Verilog, and compiler intermediate representations. It combines ideas from [MAP-Elites](E10.md), island populations, and LLM program synthesis. The paper describes the database as inspired by these approaches; it does not disclose enough archive descriptors, migration rules, or parameters to reconstruct an exact canonical MAP-Elites implementation. Compared with [Darwin Gödel Machine](E06.md), the outer search infrastructure is fixed here, while the programs being optimized can themselves implement search.[^2]

The enabling asymmetry is **expensive discovery, cheaper verification**. Checking a proposed integer sphere configuration is much easier than finding it. This asymmetry is weaker for noisy runtime measurements or an LLM’s judgment of simplicity, which must not be treated as equivalent evidence.

## The complete search loop

The user provides an initial program with designated editable blocks and an `evaluate` function returning scalar metrics to maximize. Even a rudimentary initial program is acceptable. The system samples prior programs, their scores, and useful outputs; adds problem descriptions and optional human material such as mathematical papers; and asks a Gemini 2.0 Flash/Pro ensemble for edits. Edits can be exact search-and-replace patches or full rewrites of small programs. Sampling different prompt templates and evolving a separate collection of metaprompts vary the proposal process.[^2]

Candidates pass an evaluation cascade: inexpensive validity checks reject obvious failures, while promising candidates receive more expensive evaluations. The asynchronous controller overlaps proposal, evaluation, and database work. Some evaluations can consume roughly 100 compute hours, so throughput and resource utilization matter more than minimizing the latency of every individual candidate. Typical searches use thousands of proposals, compared with the millions associated with earlier FunSearch examples; this is a descriptive comparison, not a controlled equal-cost experiment.

The database preserves multiple useful programs, rather than only the current scalar winner. Multiple metrics can expose different useful behaviors, and separate islands help maintain diversity. However, the paper does not isolate each database mechanism experimentally. Early filtering also creates a possible bias: a candidate that looks weak on a cheap proxy may never receive the evaluation on which it would excel.

For mathematical searches, the loop sometimes passes the best construction already found into the next proposed search heuristic. Thus both the search program and its starting state improve. This is sensible for obtaining a record, but comparing such a descendant with an initial program from a fresh state would conflate algorithm improvement with a better starting construction.

## Matrix multiplication: what rank measures and what changed

Multiplying an `m × n` matrix by an `n × p` matrix can be expressed as a tensor decomposition into `R` outer products. Each term corresponds to one multiplication of two linear combinations of input entries; the outputs are linear recombinations of these products. A valid lower-rank decomposition therefore uses fewer **scalar multiplications within this bilinear formulation**. It may use more additions, complex arithmetic, or numerically awkward coefficients. Rank alone is not a wall-clock benchmark or a claim about the best asymptotic matrix multiplication exponent.[^3]

The starting search minimizes tensor reconstruction error with gradient descent and Adam. Evolved changes include AdamW, altered initialization scale, noise, gradient clipping, learning-rate cycles, regularization toward integers or half-integers, penalties on large coefficients, and hyperparameter searches. Candidate fitness combines the best rank found and the fraction of seeds reaching that rank across multiple target tensors. Rounding coefficients is only a proposal for a certificate: the rounded decomposition must still reconstruct the required tensor.

The appendix prints a long evolved optimizer, making its mechanisms inspectable but not providing clean causal ablations for each change. Its so-called hallucination loss perturbs numerical parameters; it is unrelated to factual hallucination by language models. In the printed code, reconstruction is computed before that perturbation, so the perturbation affects subsequent regularization rather than the already computed reconstruction term. Likewise, a distance regularizer taking the minimum of real and imaginary errors does not itself force both components to be near allowed values. An independent final identity check is therefore essential.

Across **54 tensor shapes**, AlphaEvolve matches the previous bound on 38, improves 14, and is worse on 2. It matches or improves all tested shapes with dimensions at most 5. Larger cases face memory limits when running 1,000 seeds on one GPU. The improved multiplication counts are:

Real inputs can be embedded into complex arithmetic, but this does **not** mean 48 real multiplications.

The companion notebook checks factor shapes, reconstructs the entire tensor using `einsum`, and requires exact array equality, rather than testing a few random matrix products. This is stronger evidence for that supplied decomposition than stochastic examples, although this review did not run it.[^8]

## Mathematics: all thirteen reported improvement families

The authors report trying more than 50 curated problems across several branches, rediscovering best known results in roughly 75% and improving them in roughly 20%. The exact denominator and complete per-problem success/failure ledger are not supplied. These percentages must not be merged with the separate 54-tensor experiment. Mathematicians helped select and formulate problems; the system did not autonomously identify the entire research agenda.[^4]

Most results are **constructive bounds**: one valid example improves an upper or lower bound on an unknown optimum. It does not close the problem. The appendix’s thirteen families are:

| Family | Objective and construction | Reported change and meaning |
| --- | --- | --- |
| B.1 Nonnegative convolution inequality | A 600-interval step function minimizes the peak of `f*f` relative to squared integral mass | Upper bound on the largest universal constant: 1.5098 → 1.5053; lower bound 1.28 remains |
| B.2 Convolution norm inequality | A 50-interval nonnegative step function maximizes `‖f*f‖₂²/(‖f*f‖₁‖f*f‖∞)` | Lower bound on the smallest valid constant: 0.88922 → 0.8962; upper bound 1 remains |
| B.3 Signed convolution inequality | A 400-interval signed step function optimizes a peak ratio | Paper reports upper bound 1.45810 → 1.4557; the later notebook distinguishes two inequivalent objectives, discussed below |
| B.4 Fourier uncertainty | Hermite/Gaussian and later Laguerre constructions optimize where a function and its Fourier transform stop being negative | Initial 0.3523 → 0.3521 is superseded within the appendix by acknowledged prior 0.3284 and a refined 0.3216 construction |
| B.5 Erdős minimum overlap | Complementary functions `f+g=1` on `[-1,1]`, with fixed mass, minimize the worst translated overlap | Upper bound approximately 0.380927 → 0.380924; lower bound 0.379005 unchanged |
| B.6 Sum/difference sets | Explicit finite integer sets feed an existing theorem about relative growth of `U−U` and `U+U` | Lower bound 1.14465 → 1.1479 with 2,003 elements, then 1.1584 with 54,265; upper bound 4/3 unchanged |
| B.7 Hexagon packing | Pack 11 or 12 unit regular hexagons into a regular hexagon of minimum side length | 3.943 → 3.931 for 11; 4 → 3.942 for 12 |
| B.8 Point separation | Minimize the ratio of largest to smallest pairwise distance | **Squared** ratio 12.890 → 12.889266112 for 16 planar points; 4.168 → 4.165849767 for 14 points in 3D |
| B.9 Heilbronn triangle | Place 11 points in a unit-area triangle to maximize the smallest triangle formed by any triple | Lower bound about 0.036 → greater than 0.0365 |
| B.10 Heilbronn convex region | Analogous smallest-triangle objective in a unit-area convex region | 13 points: 0.0306 → 0.0309; 14 points: 0.0277 → 0.0278 |
| B.11 Kissing number | Construct nonoverlapping unit spheres that all touch one central unit sphere in 11 dimensions | Lower bound 592 → 593; exact kissing number remains unknown |
| B.12 Circles in a square | Fit nonoverlapping circles inside a unit square, maximizing the **sum of radii** | 26 circles: about 2.634 → 2.635; 32 circles: 2.936 → 2.937 |
| B.13 Circles in a rectangle | Choose a rectangle of perimeter 4 and pack 21 circles to maximize summed radii | About 2.364 → 2.3658 |

The paper calls the convolution problems autocorrelation, but its displayed `f(t−x)f(x)` integral is an autoconvolution. Bound direction matters: minimizing a counterexample ratio can lower an upper bound on a universal constant, while maximizing a witness can raise a lower bound. Circle radius sums are not packing area; squared distance ratios are not unsquared ratios.

Several precision and formulation issues require explicit handling. Figure 5 gives 12.8889 for the planar distance example, while the appendix gives 12.889266112; this note uses the appendix and does not reconcile them by inventing rounding. The circle and minimum-overlap summaries also differ in displayed precision. More substantially, B.3 in the paper uses `max |f*f|`, whereas the January 2026 notebook associates 1.4557 with `|max(f*f)|`. The notebook separately reports 1.4993 → 1.4688 for `max |f*f|`. These objectives differ for signed functions. Therefore the paper’s 1.4557 should not be presented as an independently verified bound for its displayed absolute-peak formula.[^8]

For uncertainty, the initial 0.3521 is not the final best claim: the appendix acknowledges stronger prior work and adds 0.3216. The verification notebook builds normalized self-Fourier functions, including extra coefficients needed for constraints, and checks the **last sign-changing root**. A largest root without a sign change is not the same boundary. Its Hermite implementation is more specific than the paper’s abbreviated polynomial description; converting a boundary construction with `f(0)=0` into the stated strict-sign theorem also requires the underlying mathematical argument. This is a construction with accompanying numerical/symbolic checks, not a complete proof of every analytic premise reproduced here.

The kissing-number certificate is especially instructive. A finite nonzero set `C` whose minimum pairwise distance is at least its maximum norm yields a valid configuration after mapping each point to `2x/‖x‖`. The distance condition bounds pairwise angles below by 60 degrees; normalized centers then lie two units from the origin and at least two units apart. The companion verifier rounds the supplied coordinates to integers and checks squared norms and distances with integer arithmetic. A successful check certifies that concrete witness, rather than asserting that 593 is maximal.

## Engineering: four applications and their evaluation boundaries

**Borg scheduling.** The evolved heuristic ranks machines that have already passed upstream resource-feasibility checks. It balances CPU and memory fit using request-to-available-resource ratios and terms comparing those ratios. Historical simulations guide search, more recent unseen data tests the candidate, and fleet deployment reportedly recovers **0.7% of average stranded compute resources**. This is not a universal 0.7% energy or throughput gain. The published short formula assumes meaningful positive denominators; upstream handling of zero-resource edge cases is part of the operational contract. Dataset sizes, deployment duration, and a complete causal measurement protocol are not disclosed.[^5]

**Gemini kernel tiling.** The task selects matrix tiling parameters for Pallas/JAX kernels under hardware and memory constraints. Half of collected real kernel shapes are used for training and half held out. Real TPU measurements produce an average **23% kernel speedup** and a reported **1% reduction in overall Gemini training time** after integration. The latter is the relevant end-to-end result; neither number describes model-quality improvement. Exact shape counts and full hardware/search budgets are not given.

**TPU arithmetic circuitry.** AlphaEvolve modifies Verilog while checking functional equivalence and optimizing implementation properties such as area and power. It removes unnecessary bits from a key arithmetic circuit, and human designers inspect the result. However, downstream synthesis independently discovers the same optimization. The paper therefore does not establish a separately quantifiable incremental final-silicon benefit from this edit, and it does not supply a general chip-level percentage saving.

**FlashAttention compiler code.** Evolving XLA intermediate representation improves one important GPU attention configuration by **32%**, with **15%** improvement for associated pre/postprocessing. These percentages concern separate measured components and cannot be added into a 47% end-to-end gain. Random input comparisons guide search; human experts subsequently establish the final algorithm’s all-input correctness according to the paper. This is not a published mechanically checked proof, nor a claim covering every attention shape and GPU.

## Ablations, compute, and reproducibility

Figure 8 compares three independent runs for matrix-multiplication and kissing-number searches. Removing evolutionary feedback, extra context, full-file editing, the large model, or metaprompt evolution weakens the final tensor result. The last three variants are not all tested on the kissing-number family. For kissing numbers, removing context is even worse late in the run than repeatedly sampling from the initial program without evolutionary feedback; the components do not form a universal ordered ladder.[^6]

The horizontal axis is a **fraction of compute budget**, not a disclosed absolute number of GPU hours. The vertical aggregate is not a benchmark pass rate. Shading reflects target-level variation averaged over runs, not a confidence interval proving every pairwise difference significant. In particular, the metaprompt gap is relatively modest and overlapping variation should not be overinterpreted.

These studies support the usefulness of iterative feedback and broad editing in these domains. They do not separately isolate MAP-Elites versus islands, cascade filtering, each tensor optimizer mutation, or whether the model ensemble beats a large-model-only alternative at equal cost. Full search infrastructure, proprietary workload data, and all configurations are not reproduced by the public mathematical-result notebook. The discussion describes infrastructure improvements over months, not measured rapid recursive intelligence growth.[^7]

## Concrete implications for Everdict evolution

The proposed Everdict architecture already separates platform authority from driver search. AlphaEvolve suggests implementing the following experiments within that boundary, rather than immediately importing an unrestricted self-modifying loop:

1. **Archive versus champion-only search.** Keep immutable candidate bytes and measured behavior descriptors. Compare equal-budget runs using only the incumbent, a simple diverse archive, and a more structured quality-diversity archive. Match evaluated candidates, executor cost, and selection exposure. Neutral or temporarily inferior candidates may remain eligible parents without becoming the active agent.
2. **Measured evaluation cascades.** Filter syntax/build failures cheaply, then use selection tasks, and reserve confirmation for candidates selected under the campaign contract. Audit a random sample rejected by the cheap stage to estimate missed useful candidates. The driver must not rewrite the platform’s validity checker or confirmation ledger.
3. **Certificate-bearing proposals.** For edits claiming a precise invariant, require the candidate to supply a checkable witness or test artifact while the platform owns the checker. A generated assertion alone is not evidence. Log the exact source, evaluator, dependencies, task split, and reconstructed candidate digest.
4. **Separate improved state from improved procedure.** Test a learned curator or search driver both with its accumulated archive and from standardized fresh history. Report these as different outcomes, just as an improved mathematical starting construction differs from a universally better search algorithm.
5. **End-to-end cost and utility.** A shorter prompt or faster helper is analogous to fewer scalar multiplications: a useful component measurement that still needs whole-task success, latency, token cost, and regression checks. A kernel-style percentage must not be reported as agent-level improvement.

Metaprompts, archive curation, and proposal selection belong in driver experiments under the current [first-loop proposal](../evolution-first-loop.md). Disclosure tiers, immutable evidence, family-level confirmation accounting, and adoption authority remain platform mechanisms. The paper motivates these experiments; it does not show they already work for Everdict.
