# R31 — ALFWorld: learning abstract procedures and testing their transfer

ALFWorld aligns an interactive text world with an embodied household simulator. Its original paper tests whether an agent can learn high-level procedures cheaply in text and transfer them to visual, physical interaction. Later skill-evolution papers often use only the text benchmark, which is a materially easier interface than the original embodied task. This explanation follows arXiv 2010.03768v2 and distinguishes the benchmark, the BUTLER agent, and the transfer experiments.[^1]

## The central principle: abstraction can simplify learning

A household goal such as heating an object and putting it away requires finding the object, acquiring it, finding a suitable appliance, changing its state, and placing it at the destination. The abstract procedure can transfer across rooms even when object appearance and geometry change. Learning all of this directly from pixels mixes planning, recognition, navigation, and manipulation failures.

ALFWorld separates those concerns. It combines TextWorld's symbolic, language-based games with ALFRED tasks in the THOR simulator. A shared representation makes text actions correspond to embodied subgoals. This builds on interactive text environments, embodied instruction following, hierarchical policies, and symbolic task-and-motion planning. Its distinctive contribution is an aligned, interactive text environment in which a policy can practice before acting through a visual interface.[^2]

Abstraction is also a source of error. Text may permit placing an object in a receptacle without modeling whether it physically fits. Thus a procedure can succeed in the cheap environment while remaining infeasible in the richer one. That gap is central to interpreting the results and to designing an Everdict development-versus-confirmation pipeline.

## Tasks, splits, and the meaning of unseen

The paper uses six ALFRED task types and excludes slicing and portable-container tasks. It gives only the goal description, omitting ALFRED's step-by-step human instructions. The simulator spans 120 rooms across kitchens, bedrooms, bathrooms, and living rooms.[^3]

| Task type | Train | Seen validation | Unseen validation |
|---|---:|---:|---:|
| Pick and place | 790 | 35 | 24 |
| Examine under light | 308 | 13 | 18 |
| Clean and place | 650 | 27 | 31 |
| Heat and place | 459 | 16 | 23 |
| Cool and place | 533 | 25 | 21 |
| Pick two and place | 813 | 24 | 17 |
| Total | 3,553 | 140 | 134 |

Seen validation uses familiar task instances and rooms with changed object locations, quantities, and appearances. Unseen validation uses new task instances in rooms absent from training, although object–receptacle combinations can overlap. Unseen therefore refers to this defined room/task distribution, not new task types or completely unfamiliar object semantics.

The All Tasks model is one jointly trained policy. Rows for individual task types can instead represent separately trained policies. The All Tasks score is not the arithmetic average of the specialist rows. This distinction matters when later work compares a single general agent against numbers from the original paper.

## How the text and embodied worlds are aligned

PDDL describes objects, locations, containment, open/closed states, and action preconditions. A text engine applies symbolic rules to update this state, while templates turn the state and last action into observations. Opening a receptacle changes its predicates and reveals contents; an invalid action can leave the state unchanged.[^3]

Text actions include navigation, taking, putting, opening, closing, toggling, heating, cooling, and cleaning. High-level heating represents several lower-level physical actions, while a text navigation command abstracts away a route. The text agent sees a partial observation and an initial list of navigable receptacles rather than the full hidden state.

The embodied environment supplies images and accepts primitives such as moving forward, rotating, looking, picking up, putting, opening, and toggling. A controller must translate the text command into these actions. Merely measuring success in the text interface does not test visual object detection, physical reachability, collision handling, or actuator reliability.

## BUTLER's brain: memory, copying, and action generation

BUTLER has three components: a text policy called Brain, a visual state estimator called Vision, and a controller called Body. Brain encodes the goal and observations, combines them with a recurrent state, and generates an action one token at a time.[^4]

Its embeddings are initialized from pretrained 768-dimensional BERT embeddings and remain frozen. The smaller trainable encoder uses convolutional layers, self-attention, and a feed-forward block with hidden size 64. Context–query attention aligns goal words with observation words. A GRU maintains a recurrent summary across steps, while an explicit queue retains five recent unique observations.

The initial observation is retained separately because it lists receptacle names. The decoder combines vocabulary generation with a pointer distribution over input tokens. This lets it copy an unfamiliar object's or receptacle's name instead of having to invent the exact string. The mixture is learned: at each token, a gate weights generated and copied probabilities. Retaining the original name list thus serves both memory and action authoring.

A fully deterministic decoder can repeatedly issue an invalid action after receiving an uninformative failure observation. At evaluation, BUTLER uses beam search only after failure: width ten, take the top five alternatives, and try them in order until one succeeds. This is a recovery heuristic over action sentences, not a tree search planning entire embodied trajectories. The default successful path uses greedy decoding.

## Learning with DAgger rather than modern LLM reinforcement learning

The main policy is trained by imitation learning with DAgger. The agent interacts with the environment, and a rule-based expert supplies the appropriate action at states the agent visits. This addresses the distribution shift of behavior cloning: a policy trained only on expert trajectories may not know how to recover after its own mistake.[^5]

Expert assistance decreases from 100% to 1% over 50,000 episodes. The implementation uses Adam at learning rate 0.001, batches of ten environments, a replay buffer capped at 500,000 episodes, and updates every five collection steps. Training samples batches of 64; recurrent samples use four consecutive transitions, the first two for state estimation and the last two for learning. Episodes allow fifty steps, and action strings allow twenty tokens.

A preliminary terminal-reward RL approach struggles because generating a grammatical, relevant command from scratch rarely produces useful feedback. This does not establish that later pretrained LLMs cannot learn ALFWorld with RL: BUTLER's architecture, initialization, exploration, and supervision differ substantially from modern Skill1 or SkillOS systems.

The source is inconsistent about duration: the implementation appendix says all text agents train for 50,000 episodes, while §5.1 says 100,000 for the text generalization experiment. A reproduction must resolve this for the particular table rather than silently assume one common budget.

## Vision, navigation, and what zero-shot transfer does not mean

Vision uses Mask R-CNN pretrained on MSCOCO and fine-tuned on 50,000 labeled images from ALFRED training scenes. The fine-tuning lasts four epochs with batch eight and learning rate 5×10^-4, recognizing 73 object classes. Detected classes and masks become template descriptions and instance identifiers. Thus the overall system has embodied visual training data; zero-shot refers to transferring the text policy without embodied policy training.[^4]

Body uses detected masks for manipulation and an A* navigator for movement. Each episode receives a prebuilt grid map with receptacle classes and interaction viewpoints. This is a strong environmental prior, explicitly acknowledged by the authors. The agent is not discovering a complete navigation map from raw vision alone.

The oracle variant supplies ground-truth state estimation and object detections and teleports between locations. It helps diagnose perception/navigation bottlenecks, but physical action constraints can still differ from the text world. One paragraph attributes the remaining oracle gap partly to detector and navigation errors despite defining those components as perfect. That attribution is internally inconsistent; such errors explain the non-oracle gap, not an ideal oracle's residual by definition.

## Interactive training versus a static demonstration corpus

The main transfer comparison uses BUTLER's DAgger against an identical Seq2Seq architecture trained by behavior cloning from an equally sized expert corpus. This controls architecture and episode count while changing whether training follows states encountered during interaction.[^6]

For the jointly trained All Tasks policy, embodied seen/unseen success is 6%/5% for Seq2Seq and 19%/10% for BUTLER. Partial goal-condition success rises from 15%/14% to 31%/20%. The oracle BUTLER reaches 37%/26%, and the corresponding text policy reaches 40%/35%. The large gap between abstract and embodied results remains even when interactive learning helps.

Specialists show mixed outcomes. For unseen pick-and-place, BUTLER reaches 24% versus Seq2Seq 17%; clean-and-place rises from 12% to 22%; cool-and-place falls from 21% to 19%. Examine-under-light remains zero strict success in the non-oracle unseen condition. The method improves several tasks without solving embodied generalization broadly.

The study trains eight seeds and selects the best TextWorld agent separately for each seen/unseen split before embodied evaluation, then averages three evaluation runs. This is not the mean performance of eight independently selected deployments. Because the abstract and embodied tasks are aligned, selecting on the abstract counterpart also means the underlying task family is not a wholly untouched confirmation pool. It is still zero-shot modality transfer, with a specific model-selection procedure.

## Human language and the training-domain comparison

Training goals use two templates per task type. Human-written evaluation goals introduce 66 unseen verbs and 189 unseen nouns. All Tasks success drops to 8% seen and 3% unseen, with partial completion 17% and 12%. Some specialist transfer remains, but natural language variation exposes another gap. Pretrained embeddings and copying can help without eliminating it.[^7]

A separate experiment compares 50,000 episodes of embodied-only training, text-only training, and a hybrid that samples text with 75% probability and embodiment with 25%. All are evaluated with oracle perception and control; the paper reports peak performance separately by split.

| Training strategy | Seen success | Unseen success | Training episodes/second |
|---|---:|---:|---:|
| Embodied only | 33.6% | 23.1% | 0.9 |
| Text only | 27.1% | 34.3% | 6.1 |
| Hybrid | 21.4% | 23.1% | 0.7 |

Text training is about 6.8 times faster by these values, rounded to seven times, and transfers better to unseen rooms. Embodied-only is better on seen rooms. The hybrid is not automatically better than either. These are simulator-training rates under the paper's setup, not an inference speedup or a general sevenfold gain from any textual memory.

## Text generalization, unimodal baselines, and component ablations

In Table 4's All Tasks text evaluation, BUTLER succeeds on 40% seen and 37% unseen; greedy decoding without failure recovery scores 19%/22%; static Seq2Seq scores 10%/9%. Beam recovery and interactive imitation both matter. Training scores exclude beam recovery, so a higher validation score than training score is not directly evidence of an easier-to-harder generalization paradox.[^8]

This table selects seeds by best final training score, unlike Table 2's split-specific TextWorld selection. Its 37% unseen All Tasks value also differs from Table 2's 35%. Preserve the distinction instead of merging the tables into one run.

Unimodal embodied baselines keep the action space and controller but replace textual observations with ResNet-18 or Mask R-CNN FPN features. They obtain seen/unseen 10.0%/6.0% and 11.4%/4.5%, versus BUTLER 18.8%/10.1%. An action-history-only agent scores zero. These results support useful state abstraction in the tested architectures; they do not prove language always outperforms vision.

Additional curves vary observation-queue length, keeping the initial observation, recurrent aggregation, and the number of training games. The initial receptacle list particularly helps unseen name generation; recurrence helps history-dependent decisions; too few games encourage high training performance and poor generalization. The paper also reports that candidate-action lists overfit and fail to transfer, while enumerated templates can create thousands of candidates. Modern experiments that supply admissible actions therefore use a different information interface from original BUTLER.

## An Everdict experiment based on aligned abstraction

Create a cheap development environment that preserves the task's meaningful state transitions, then confirm candidate procedures in a richer execution environment. For example, a document-editing dry run can check operations and required fields, while confirmation opens the exact produced files and verifies formulas, layout, and references. This is an Everdict proposal inspired by the paper, not a result demonstrated by ALFWorld.

Measure the transfer gap explicitly. A candidate that passes the abstract check but fails rendering should retain both outcomes with the environment version and artifact digest. Keep task families separate across search and confirmation; selecting a candidate on an aligned abstract copy still discloses information about that family.

Separate planner, observation translator, and tool/controller changes. Test a recovery policy that proposes a genuinely different action after failure and updates its state, with a fixed attempt budget. Preserve original observations and provenance when a curator produces a compact state summary. ALFWorld's lesson is that abstraction and feedback make learning easier, while the gap between the abstraction and actual execution must remain visible.
